# .NET 8 WinForms 采集网关开发规范

## 1. 确立边界与基线

先阅读仓库 `README.md`、`AGENTS.md`、[项目架构](../../../docs/architecture.md) 和实际代码。比较参考项目时，阅读 [结构参考](references/architecture.md)，固定参考提交。以用户要求的 `.NET 8 + WinForms` 为技术基线，不因上游升级到 .NET 10 而修改目标框架。

用户要求将源 `Plugins/Drivers` **全部迁移**。维护 `docs/driver-migration-manifest.json` 中的 12 个原驱动工程、65 个原读取方法、74 个原配置参数和全部来源文件，不得以只留下接口、模拟实现或少量协议来代替迁移。源代码经 .NET 8 编译和统一适配器接入界面；源码完整、程序集被打包、界面可配置、现场验证是分别需要记录的事实。

保持当前范围：OPC UA 仅通过迁移的 `OPC.UaClient` 驱动用于南向采集。对外服务端已按用户要求彻底移除；不恢复其工程、配置字段、UI、服务端依赖或兼容层。变更与本轮实际验收入口见 [服务端移除记录](../../../docs/opc-ua-service-removal.md)。

将需求分为已实现、待实现、待设备验证。保持设备/点位稳定 ID、地址口径和权限。本次用户明确处于开发环境，只保留最新功能，不保留旧 SQLite 历史且不向下兼容。配置只接受 `SchemaVersion=3`；不添加旧 JSON/SQLite 迁移、历史归档或无操作兼容接口，旧版本直接拒绝，示例和测试使用新版结构。

交付可启动、可配置、可采集、可查询、可上报的程序。仅实现驱动接口不能标记对应 PLC 协议已支持；模拟数据必须明确显示来源。只把本机回环验证描述为协议自动测试，不等同于实机验收。

## 2. 维持工程职责

| 工程 | 职责 | 约束 |
|---|---|---|
| `EdgeGateway.Model` | 配置、采样、质量、运行状态、历史查询模型 | 不引用 UI、数据库或通信库 |
| `EdgeGateway.Abstractions` | 驱动工厂、异步驱动、存储、上报、日志契约 | 仅依赖 Model |
| `EdgeGateway.DataAccess` | SQLite 配置事务、JSON 交换、文件 outbox/RPC、MySQL/PostgreSQL/Oracle 连接器 | 不访问控件或设备 |
| `EdgeGateway.Service` | 配置事务、点表交换、采集调度、重连、工程量、报警、插件、平台报文规则与 RPC | 不引用 WinForms、MQTTnet 或具体传输工程 |
| `EdgeGateway.Application` | `IGatewayApplication` 用例、配置命令、预览确认、查询和快照；编辑器元数据目录 | 复用 Service，不暴露驱动连接、存储实例或控件 |
| `EdgeGateway.Hosting` | 数据目录占用、配置/存储/日志/驱动组装，应用入口及资源释放 | 不实现页面或采集循环，不冒充 Windows Service |
| `EdgeGateway.Infrastructure.Mqtt` | MQTTnet、TLS、连接、QoS 1、订阅及传输确认 | 通过契约接入运行时；可复用 Service 纯平台规则，禁止反向引用 |
| `EdgeGateway.IotGateway` | 12 个源驱动的工厂、元数据、接口和工作线程适配 | 不依赖 UI；保留原方法与参数语义 |
| `PluginInterface` | 迁移后的上游驱动接口、属性和数据契约 | 不引入上游 Web/WTM/数据库依赖 |
| `Plugins/Drivers/EdgeGateway.Driver.*` | 协议连接、读取、写入、报文编解码 | 返回原始值与质量；不直接向云端上传 |
| `Plugins/Drivers/<原目录名>` | 全部 12 个迁移驱动及其协议辅助源码 | `net8.0`，保留来源与许可，依赖随宿主发布 |
| `EdgeGateway.WinForms` | 桌面交互、配置草稿、实时监控、历史趋势、日志 | 直接工程引用收敛至 Application/Hosting，业务调用应用入口；不自行保存配置或创建运行时/存储/驱动 |
| `EdgeGateway.Tests` | 关键故障语义、协议回环、持久化和并发测试 | 核心测试在非 Windows 环境可运行 |

保持一个标准 `.sln`，依赖单向。由 `GatewayHost` 组装并持有资源，`IGatewayApplication` 承接桌面用例，`GatewayRuntime` 保留采集生命周期与设备/通道互斥。应用层命令串行构建最新候选，不复制运行时锁。通过传递引用能访问某个实现不代表窗体可以越过应用边界。新增协议建立独立驱动工程；接口变更同步更新实现、UI、测试和文档。

## 3. 以完整数据链实现功能

按“配置校验 → 驱动连接 → 原始采样 → 工程量转换 → 质量与报警 → 默认采集日志 / 可选外部数据库 → 遥测文件落盘 → MQTT 确认 → 清理已发送记录”实现闭环。

- 为每台设备创建独立驱动与可取消的采集任务。同设备读写互斥；所有采集、诊断、写入和读回按“设备锁 → 通道锁”顺序执行。同通道串行，不同通道并行；通道间隔从上批完成后计算，排队不消耗实际通信超时。通道调度不等于多个驱动共享串口连接。
- 新异步驱动使用 `CancellationToken`，为每次连接和通信设置有限超时，禁止 `Thread.Sleep`、无限等待和未观察的后台任务异常。原同步驱动通过专属工作线程适配；超时后隔离未结束操作，不复用同设备，不宣称取消令牌能强制终止本机库。
- 在同一生命周期锁内串行化启动、停止与配置应用，以稳定设备 ID 定位目标。停止一台设备只取消并等待该会话及其写锁，再释放驱动，不中断其他设备或共享采集输出/MQTT 任务；最后一台停止时才处理采集输出并有界排空外库队列并关闭共享任务。写入关联设备取消令牌，在取得写锁后再次检查会话活跃状态。保留自动启动全部启用设备与退出停止全部设备的路径。
- 对同步厂商调用，超过关闭宽限时保留隔离线程与设备租约，待原调用退出后在原线程清理；不承诺取消令牌能强制终止本机调用，重复启停不得无限创建新调用。
- 网络失败后指数退避并设上限；重新连接失败不得占满 CPU、刷屏或拖慢其他设备。
- 点位扫描使用单调时钟，到期点组成读取子集；周期 0 继承设备，不补发积压轮次。故障降速等待时释放通道，恢复真实读取后回到正常周期；表达式错误不能触发通信重连。通信批次数不得冒充底层帧数。
- 保存原始值与工程值，按 `工程值 = 原始值 × Scale + Offset` 转换。拒绝 NaN、Infinity 和写入时无法逆转换的参数。
- 保留迁移驱动的字符串、64 位整数、时间和结构值；不将所有数据强制转成 double，不因超过 double 精度而改变原始值。非数值数据不做倍率、偏移或数值报警。
- 读取失败产生 Bad 或 Uncertain 质量、错误信息和本次时间戳，不将旧值标记为新的 Good 数据。
- 停止设备诊断创建短生命周期真实驱动并释放，运行设备诊断复用已有会话和锁，不能把缓存或端口连通当作读点成功。无启用点位仅能报告连接成功与 Uncertain。
- `WriteVerifiedAsync` 只下发一次写入，随后在同一设备/通道租约内有界主动读回。区分 Submitted、Matched、Mismatched、TimedOut、Failed、Cancelled，保留命令 ID、实际尝试与提交状态；64 位整数精确比较，浮点以实际线类型的舍入值和显式容差核对。正常返回且会话仍活跃、操作未取消的真实读回样本，在设备锁内发布到共享最新值，保留实际质量与源时间戳；匹配与不匹配都按实际读值发布，超时或取消的迟到结果不得变成新 Good。桌面与 MQTT 共用该快照，禁止另建写入成功缓存掩盖后续写入、停止或重启。普通诊断不修改最新值或历史；采集更新缓存也须在设备锁内完成，避免旧 Good 采样覆盖写后的 Uncertain。
- 单点表达式统一使用 `NumericExpression`，`x` 为倍率/偏移后的工程值。限制语法、长度、节点数、深度和幂范围；预览与运行同一解析器，非零下溢、溢出、除零均明确失败。表达式点只读，不做任意脚本执行、跨点依赖或自动反向求解。
- 阈值报警仅在进入、切换或恢复状态时记录，避免每次采样重复记录。通讯异常和阈值异常分别表达。

## 4. 严格处理协议数据

开发驱动前阅读 [驱动与测试规范](references/driver-development.md)。新增驱动必须实现 `IDriverFactory` 和 `IDeviceDriver`，公开稳定 ID、名称、能力说明和配置验证。

维护源驱动时，通过 `EdgeGateway.IotGateway` 适配 `PluginInterface.IDriver`，反射并保留全部 `ConfigParameter` 和 `Method` 元数据。WinForms 必须能编辑驱动专用参数并选择读取方法，不要求用户手写内部 JSON。OPC 默认使用 `ReadNode`；源 Modbus 默认选择真实寄存器读取；演示返回当前时间的方法必须标识，不能冒充现场数据。未实现的 `WriteAsync` 不得公开为可写能力。

Fanuc FOCAS 原生 DLL、HslCommunication 有效授权、OPC DA COM/DCOM 和现场服务器由实际运行环境提供。缺少依赖时明确失败；不能制造 DLL、绕过授权、接受全部证书或用模拟值填补数据。构造、调用和释放 COM 对象保持同一 STA 线程。

Modbus 地址统一使用 0 基偏移。设备手册的 40001/30001 是参考地址时，先确认转换规则；不得自动猜测。校验站号、地址范围、读长度、数据类型、寄存区和字节序。禁止写入离散输入和输入寄存器。

TCP 读取按协议长度组帧，不假设一次 `ReadAsync` 得到完整报文。校验 MBAP transaction/protocol/unit/length、功能码、字节数与异常帧。RTU 校验站号、CRC、帧间隔和串口参数。连接超时或帧损坏后清理传输状态，避免下一次请求读取前次残留响应。

记录 16/32/64 位数据的明确字节序规则；以固定报文向量验证，不能仅使用编码后再解码的自洽测试。整数写入必须检查小数和边界，不能静默截断或溢出。

当前 RTU 按设备独占串口。新增同串口多站号功能时，先设计共享总线调度与生命周期，不通过删除重复串口校验直接开放。

## 5. 保持数据与配置可靠

- 配置在 SQLite 中保存 schema 3 的 JSON 内容，UTF-8 JSON 文件只作导入/导出；使用稳定 Guid、枚举名称和 `SchemaVersion`。设备、点位与导入使用独立候选，经 `IGatewayApplication` 基于最新配置提交，内部通过 `GatewayRuntime.ApplyConfigurationAsync(candidate, configurationStore, cancellationToken)` 在生命周期锁内校验、以 SQLite WAL/FULL 事务更新当前及上一份同版本配置，再应用运行时；禁止 UI 自行保存或调用仅适合全停初始化的 `Configure`。首次启动默认设备前由应用层先落盘，保持重启后的设备和点位 ID 稳定。
- 仅在配置数据库没有当前配置时创建演示配置。损坏、无效或版本不支持的配置应显示错误，不静默重置；不读取旧 gateway.json / gateway.db。
- 运行时使用配置深拷贝，允许设备运行期间新增、编辑、删除、追加导入设备与点位。新增设备与原本停止的设备保存后保持停止；仅重新建立配置有实质变化且原本运行的目标会话，禁用或删除则停止该目标。保留其他设备的会话、样本、状态和共享工作任务；单台重启不重建共享任务。比较值时忽略字典键顺序，保留点位顺序语义。完整校验仍拒绝同串口多个启用设备，不以停止状态绕过约束。
- 校验失败、保存失败或提交前取消不得修改现有会话与内存配置；原子保存提交后必须完成运行时同步，不再响应调用方取消。新会话连接失败进入原有可见故障与退避重连流程，不自动回滚已保存参数；“重启已调度”不能写成“设备已连接”。结果分别返回 `Added`、`Updated`、`Removed`、`Restarted`、`Stopped` 的设备 ID，停止集合不包含重启集合。详见 [运行中配置与数据闭环](../../../docs/live-configuration.md)。
- 将平台输入保存在独立草稿，可随时编辑或“重置修改”；未应用草稿不阻止按已保存设置启动。普通设备提交保留平台输入。“应用设置”从最新配置克隆且只覆盖全局/MQTT 字段，避免撤销后来设备变更；平台全局应用、数据库设置和“导入配置”整份替换仍要求所有设备停止；日志设置可在运行中应用且不重启设备，成功后才刷新平台草稿。
- SQLite 使用参数化 SQL、WAL、事务和串行写入约束。时间存 UTC，UI 显示本地时间；查询时间边界写明语义。
- `SqliteConfigurationStore.OpenCore` 返回存储实例持有的共用连接，调用方只释放命令、读取器和事务，连接统一由存储的 `DisposeAsync` 释放。驱动目录刷新成功、失败回滚后都须验证同一实例仍可保存与读取当前/上一版本配置。
- SQLite 仅保存网关/设备/点位/日志/数据库映射等配置，禁止样本、outbox、RPC 或外部数据库重试队列进入 SQLite。默认采集输出到可配置滚动 JSONL，日志等级、单文件大小、保留份数和天数可热更新；日志有界后台写入，单条/字节/条数配额和失败、丢弃计数可见。
- 外部数据库通过 `IExternalDatabaseConnector` 与 DataAccess 接入 MySQL、PostgreSQL、Oracle；每点一行模式保留类型、质量与UTC，并以稳定 event_id 去重重试；自定义字段模式绑定现有表，完整、新鲜、活跃样本才生成一行，转换不静默丢整数精度。SQL标识符验证/引用，数值参数化；只有用户显式建标准表操作执行建表，普通采集不改结构。
- 每组独立队列，连接共享行数/字节限额，数据库故障不等待采集；重试有限且计数，停止有界排空，丢弃明确可见。大样本在序列化与缓存前预检，自定义缓存只保留引用点位并另设64MiB估算配额。同连接某组成功不能抹掉其他组错误。外库内存队列不保证断电无损；自定义表重复记录须由业务唯一键处理。完整规则见 [数据记录](../../../docs/data-recording.md)。
- 遥测 outbox 先持久化再发送；Generic、ThingsBoard、ThingsPanel、IoTSharp 等待 QoS 1 PUBACK，ThingsCloud 还须收到 attributes/response 成功后才能移除。失败保留原记录，重启后继续发送；发送确认不等于最终业务入库，不能混淆诊断指标。
- 周期、变化、变化加心跳通过 `TelemetryReportPlanner` 选择样本。死区相对最后成功入队值累计，质量与错误变化独立触发；仅完整持久化后推进基线。配置变化、进程/单台设备重启重新发初值，心跳保留原采样时间。部分平台分片已经落盘时不可撤回，未落盘部分按新配置重建。
- 新快照按当前配置的启用设备、启用点位和 `UploadEnabled` 过滤。关闭上传保留本地采集与已配置的数据输出；配置变化后，等待容量或重试的未入队旧快照弃旧重建。已进入单次入队调用的快照可能完成旧内容保存，已持久化消息按原载荷继续补传，不能承诺撤回。停止但仍启用的设备可保留带 `Uncertain` 质量的旧值供快照表示停止状态。
- 保留稳定 `messageId` 以支持接收端幂等。明确“至少一次”可能重复，不能声称端到端恰好一次。
- 队列满时显式报警并保留旧消息，不静默覆盖未确认记录。根据实际行为记录新快照丢弃或回压策略。
- MQTT 密码仅从配置指定的环境变量读取；配置、日志、导出和 Git 不得包含密码。TLS 使用系统证书验证，不接受所有证书。
- 平台接入遵循 `PlatformMqttAdapter` 和 [协议说明](../../../docs/platform-protocols.md)，落实主题、标识、报文、子设备状态与响应；不能用通用 MQTT 成功替代平台协议验收。切平台类型前若有待传队列应拒绝，不能改写旧消息。ThingsCloud 绑定/属性回应和历史补传不得伪造设备在线状态。
- 同平台目标变更且有积压时，通过应用层预览取得确认凭据，由 UI 展示并确认；提交再次核对当前配置、候选和队列，不能复用过期确认。确认与错误展示留在 UI，业务约束不能只依赖按钮禁用或 MessageBox。
- RPC 默认关闭且写许可单独关闭；只允许 read/write，限制载荷、队列、速率与时限，拒绝 retained 指令。在设备锁内再核对权限；写前独立文件持久占位，重复请求重放，跨方法或不同内容同编号拒绝。未完成占位返回 Indeterminate 而非重写。去重域包括稳定的平台/网关/账号配置身份，不能用可轮换 Token 内容改变域。日志和返回不能泄漏密码。

## 6. 实现可操作的桌面界面

以中文为默认文案。将总览、设备与点位、实时数据、历史趋势、云端设置、日志、数据库和通信诊断组织为八个主页面。设备显示最近成功、连续失败次数与错误；上报诊断区分生成/持久化、发送、确认、队列和重试，计数仅代表本进程观察到的事件。所有按钮必须连接真实服务；未实现功能不得显示可操作按钮。

修改主窗体、弹窗、动态驱动参数、主题或第三方控件前，阅读 [WinForms DPI 与视觉规范](references/winforms-dpi.md) 和 [界面操作与本轮验收](../../../docs/ui-usability.md)。保持 `ApplicationHighDpiMode=PerMonitorV2` 与统一的 96 DPI 逻辑尺寸基线；通过 `DpiAwareForm` 管理初始窗口、当前显示器工作区及 DPI 切换，不在 Resize 中递归缩放控件或字体。

使用 `Dock`、`Anchor`、`TableLayoutPanel`、滚动容器和 `AutoSize`。常用文字以 10 pt 为逻辑基准，主要操作提供足够点击面积，状态同时使用文字与颜色。主窗体和弹窗统一字体、色板、间距、图标、按钮命名和确认方式；使用第三方图标时，按所属控件当前 DPI 重绘，妥善释放图像资源，保留依赖和资源许可证。

以当前可用逻辑宽度选择布局。小屏或高缩放时采用工具栏换行、卡片重排与内容滚动，保持导航、设备行启停与配置、平台应用/重置、弹窗确认和取消可达；不缩小字体以强行放下全部内容，不用固定最小窗口尺寸撑出屏幕。动态新增参数控件继承当前字体并只缩放一次，长说明按容器宽度换行，表格行高与自绘图形常量按当前 DPI 计算。

验收覆盖 1366×768、1920×1080、2560×1440、3200×2000 与 100% / 125% / 150% / 175% / 200% 缩放，并检查 100% ↔ 150% ↔ 200% 跨屏及往返无累计缩放。区分真实 Windows DPI、受控布局模拟和实机多屏结果，记录实际系统版本、工作区、DeviceDpi 与截图；未执行组合不得记为通过。

通过应用层读取线程安全快照，由 UI 定时器更新展示。后台不得直接操作控件；异步事件捕获异常，避免 `.Result`、`.Wait()` 阻塞 UI。列表使用稳定 ID 定位，刷新时保持选择、过滤、当前列和滚动位置；不能每次重绑都跳回第一行或第一列。

常用动作与低频菜单分层，菜单保留文字、禁用原因和键盘路径；按实际打开后的布局验收，不只检查触发按钮。设备身份与本行命令优先同屏，冻结区不能占满小表格。点位区显示所属设备和数量，筛选说明范围与空结果；新增、保存、删除后按设备/点位 ID 恢复明确上下文。历史输入改变时标记尚未查询，摘要与导出始终绑定上次已执行条件和结果。

平台使用分组页签和固定应用区，持续显示未应用草稿及全停限制。普通操作完成用可查看完整内容的非模态反馈说明目标、结果和时间；删除、整份替换和真实写入保留确认。保存失败仍在原编辑器保留输入，不能把成功提示代替校验或把重连已调度写成已连接。

在设备表每行提供状态、“启动”“停止”和“配置”，按被点击行的稳定设备 ID 执行，不用当前选中行代替目标。删除顶部全局启停与“保存配置”；启用状态是配置许可，与实时运行状态分别显示。启动未启用设备时拒绝；停止已运行设备不修改其启用配置。实时写入按钮按目标设备的运行状态判断，不能只检查网关是否有任意设备运行。参见 [单设备启停与自动保存](../../../docs/device-control-autosave.md)。

设备窗体只保留 `DeviceConfigurationDialog`，构造接收驱动注册表和通道列表；添加设备、编辑设备、复制设备、行内配置与普通数据列双击必须共用同一套控件及布局，不恢复重复的 `DeviceEditor`。默认显示“采集设置”，首行提供“启用设备”，并提供名称、分组、通道、驱动、周期和超时；“扫描与恢复”页维护扫描模式及降速。行内入口按被点击行的稳定设备 ID 定位；双击事件排除启动、停止、配置等操作列。运行期间设备与点位仍可编辑，提交运行目标前明确提示只影响该目标；不要因网关存在任意运行设备而把整页锁成只读。

统一窗体的 `isNew` 模式只改变新建标题和确认时生成所选驱动默认点位的行为，不引入独立编辑器或另一套表单。编辑已有设备保留设备 ID 和已有 `Tags`，允许修改名称、分组及驱动；切换驱动不得静默转换、清空或替换已有点位，必须对最终完整候选配置校验。按驱动保留独立参数草稿，切换后再返回恢复草稿，取消不修改来源对象。

迁移驱动复用原 `ConfigParameter` 元数据，内置 TCP / RTU 分别显示网络 / 串口字段；保留同一驱动的未知参数供真实校验报告，不通过删参数规避错误。设备、点位和点位导入对话框使用深拷贝及可等待的提交回调，完整候选校验、原子保存和运行时应用成功后才设置成功结果并关闭；任一校验或保存错误均在原弹窗显示并保留输入，不先关闭再尝试保存。提交期间禁止重复点击或关闭打断事务。`Enabled` 写入设备模型，绑定字段通过采集设置同步，不重复写入 `Properties`；启用不直接启动采集。参见 [参数与行内入口](../../../docs/device-configuration.md) 和 [运行中配置](../../../docs/live-configuration.md)。

手动写入要求设备运行、点位启用且允许写入，展示目标与工程值后由操作者确认。记录审计结果。不要默认启用云端远程控制或用配置导入绕过写权限。

点位 CSV 使用 `TagCsvExchange`，导出 20 个业务字段并排除 `Id`，兼容旧 17 列。缺少 Expression/ScanIntervalMs/Deadband 扩展列时，按名称更新保留原值，新点使用默认值；显式空表达式清除，已提供的数值列不得空白。使用 UTF-8 BOM、CRLF、CSV 引号及公式前缀保护；导入亦接受无 BOM UTF-8。追加和按名称更新均不删除文件未出现的点，名称不区分大小写且更新保留 ID。完整解析及驱动/全网关校验后整批提交，错误报告物理起始行与列；限制 8 MiB、2000 数据行及合并后每设备 2000 点。预览的 500 条上限不是校验上限。保留 [模板](../../../examples/tag-template.csv) 与模型一致。

区分“导入设备”的追加与“导入配置”的整份替换。追加可在其他设备运行时进行，新导入设备保持停止；整份替换要求全停并确认，先构造完整候选、校验，原子保存及运行时应用成功后生效。

## 7. 执行有意义的验证

优先测试实际风险：报文拆包、错误 transaction、功能码异常、CRC、数值边界、超时取消、重连、单设备启停/配置应用隔离与竞态、旧会话写入取消、读写互斥、保存失败不动会话及保留弹窗输入、平台草稿隔离、配置损坏、CSV 整批失败与名称/ID 语义、上传筛选、队列容量、重启补传和真实发布确认。验证保存前取消无修改、保存提交后完成同步，以及最后一台禁用与单台重启的共享任务边界。

新增能力必须覆盖通道排队/扫描降速、停止设备真实诊断、写入一次与主动读回的边界、表达式失败/恢复、变化基线及同值重启、平台实际主题与应用回应、RPC 持久去重与跨方法冲突。详情见 [Kepware 核心能力](../../../docs/kepware-core-capabilities.md)。

修改完成执行：

```powershell
python scripts/verify-driver-migration.py
dotnet restore EdgeGateway.sln
dotnet build EdgeGateway.sln -c Release --no-restore
dotnet test tests/EdgeGateway.Tests/EdgeGateway.Tests.csproj -c Release --no-build
./scripts/smoke-test-winforms.ps1
```

清单检查和核心构建测试可在安装对应 SDK、Python 和 Windows targeting pack 的构建机执行；最后一项必须在 Windows PowerShell 执行。本轮门禁要求完整功能与 20 组合布局烟测，核验八页面、七类弹窗、149 张 PNG 和 15 个完成标记；包含数据库/平台/日志隐藏页签首次创建与连续导航、菜单实际打开、平台页签、选择保持、查询条件反馈及数据库/日志配置检查，不能直接沿用上一版通过数量。这些是验收目标，只有实际产物严格匹配才能记录通过。保留通道 3 个、写入核对 4 个输入指标，新增数据库连接 16 个和日志设置 7 个输入指标；实际验证点位列表与 7 列映射单元格的焦点、滚动和完整裁剪边界。打包时再次复验并生成 `build-info.json`。跨平台编译不能替代 Windows 运行检查。迁移测试核对全部 12 个工厂、65 个方法与 74 个源参数，并覆盖适配器线程、坏质量、超时、配置类型和关键真实协议回环。真实串口、PLC、TLS 证书和现场长稳测试按 [验收边界](references/acceptance.md) 补齐。

新增或修改 TCP/HTTP 协议至少覆盖一个真实本地通信回环与一个异常场景。COM/FOCAS 等接口使用对应边界的故障、线程和依赖检查，再补实际 Windows 集成与设备验收，不搭建无关 socket 代替原接口验证。测试应验证外部行为，不为简单属性或固定布局机械编写测试。
