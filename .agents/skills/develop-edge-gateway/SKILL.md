# .NET 8 WinForms 采集网关开发规范

## 1. 确立边界与基线

先阅读仓库 `README.md`、`AGENTS.md` 和实际代码。比较参考项目时，阅读 [结构参考](references/architecture.md)，固定参考提交。以用户要求的 `.NET 8 + WinForms` 为技术基线，不因上游升级到 .NET 10 而修改目标框架。

用户要求将源 `Plugins/Drivers` **全部迁移**。维护 `docs/driver-migration-manifest.json` 中的 12 个原驱动工程、65 个原读取方法、74 个原配置参数和全部来源文件，不得以只留下接口、模拟实现或少量协议来代替迁移。源代码经 .NET 8 编译和统一适配器接入界面；源码完整、程序集被打包、界面可配置、现场验证是分别需要记录的事实。

将需求分为已实现、待实现、待设备验证。保留现有设备 ID、点位 ID、地址口径、权限和配置格式。变更序列化格式时升级 `SchemaVersion` 并定义迁移，未知版本必须报错，不覆盖原文件。

交付可启动、可配置、可采集、可查询、可上报的程序。仅实现驱动接口不能标记对应 PLC 协议已支持；模拟数据必须明确显示来源。只把本机回环验证描述为协议自动测试，不等同于实机验收。

## 2. 维持工程职责

| 工程 | 职责 | 约束 |
|---|---|---|
| `EdgeGateway.Model` | 配置、采样、质量、运行状态、历史查询模型 | 不引用 UI、数据库或通信库 |
| `EdgeGateway.Abstractions` | 驱动工厂、异步驱动、存储、上报、日志契约 | 仅依赖 Model |
| `EdgeGateway.DataAccess` | 原子 JSON 配置、SQLite 历史、持久化 outbox | 不访问控件或设备 |
| `EdgeGateway.Service` | 配置校验、调度、重连、工程量、报警、插件、MQTT | 不引用 WinForms |
| `EdgeGateway.IotGateway` | 12 个源驱动的工厂、元数据、接口和工作线程适配 | 不依赖 UI；保留原方法与参数语义 |
| `PluginInterface` | 迁移后的上游驱动接口、属性和数据契约 | 不引入上游 Web/WTM/数据库依赖 |
| `Plugins/Drivers/EdgeGateway.Driver.*` | 协议连接、读取、写入、报文编解码 | 返回原始值与质量；不直接向云端上传 |
| `Plugins/Drivers/<原目录名>` | 全部 12 个迁移驱动及其协议辅助源码 | `net8.0`，保留来源与许可，依赖随宿主发布 |
| `EdgeGateway.WinForms` | 桌面交互、配置编辑、实时监控、历史趋势、日志 | 使用服务和快照；不实现采集循环 |
| `EdgeGateway.Tests` | 关键故障语义、协议回环、持久化和并发测试 | 核心测试在非 Windows 环境可运行 |

保持一个标准 `.sln`，依赖单向。新增协议建立独立驱动工程，避免将所有协议代码堆入窗体或运行时。遵循现有接口命名与构造方式，接口变更同步更新实现、UI、测试和文档。

## 3. 以完整数据链实现功能

按“配置校验 → 驱动连接 → 原始采样 → 工程量转换 → 质量与报警 → 历史存储 → 遥测落盘 → MQTT 确认 → 清理已发送记录”实现闭环。

- 为每台设备创建独立驱动与可取消的采集任务。设备间并行，同设备读写互斥。
- 新异步驱动使用 `CancellationToken`，为每次连接和通信设置有限超时，禁止 `Thread.Sleep`、无限等待和未观察的后台任务异常。原同步驱动通过专属工作线程适配；超时后隔离未结束操作，不复用同设备，不宣称取消令牌能强制终止本机库。
- 串行化启停生命周期，以稳定设备 ID 实现独立启动和停止。停止一台设备只取消并等待该会话及其写锁，再释放驱动，不中断其他设备或共享历史/MQTT 任务；最后一台停止时才排空历史并关闭共享任务。写入关联设备取消令牌，在取得写锁后再次检查会话活跃状态。保留自动启动全部启用设备与退出停止全部设备的路径。
- 对同步厂商调用，超过关闭宽限时保留隔离线程与设备租约，待原调用退出后在原线程清理；不承诺取消令牌能强制终止本机调用，重复启停不得无限创建新调用。
- 网络失败后指数退避并设上限；重新连接失败不得占满 CPU、刷屏或拖慢其他设备。
- 保存原始值与工程值，按 `工程值 = 原始值 × Scale + Offset` 转换。拒绝 NaN、Infinity 和写入时无法逆转换的参数。
- 保留迁移驱动的字符串、64 位整数、时间和结构值；不将所有数据强制转成 double，不因超过 double 精度而改变原始值。非数值数据不做倍率、偏移或数值报警。
- 读取失败产生 Bad 或 Uncertain 质量、错误信息和本次时间戳，不将旧值标记为新的 Good 数据。
- 阈值报警仅在进入、切换或恢复状态时记录，避免每次采样重复记录。通讯异常和阈值异常分别表达。

## 4. 严格处理协议数据

开发驱动前阅读 [驱动与测试规范](references/driver-development.md)。新增驱动必须实现 `IDriverFactory` 和 `IDeviceDriver`，公开稳定 ID、名称、能力说明和配置验证。

维护源驱动时，通过 `EdgeGateway.IotGateway` 适配 `PluginInterface.IDriver`，反射并保留全部 `ConfigParameter` 和 `Method` 元数据。WinForms 必须能编辑驱动专用参数并选择读取方法，不要求用户手写内部 JSON。OPC 默认使用 `ReadNode`；源 Modbus 默认选择真实寄存器读取；演示返回当前时间的方法必须标识，不能冒充现场数据。未实现的 `WriteAsync` 不得公开为可写能力。

Fanuc FOCAS 原生 DLL、HslCommunication 有效授权、OPC DA COM/DCOM 和现场服务器由实际运行环境提供。缺少依赖时明确失败；不能制造 DLL、绕过授权、接受全部证书或用模拟值填补数据。构造、调用和释放 COM 对象保持同一 STA 线程。

Modbus 地址统一使用 0 基偏移。设备手册的 40001/30001 是参考地址时，先确认转换规则；不得自动猜测。校验站号、地址范围、读长度、数据类型、寄存区和字节序。禁止写入离散输入和输入寄存器。

TCP 读取按协议长度组帧，不假设一次 `ReadAsync` 得到完整报文。校验 MBAP transaction/protocol/unit/length、功能码、字节数与异常帧。RTU 校验站号、CRC、帧间隔和串口参数。连接超时或帧损坏后清理传输状态，避免下一次请求读取前次残留响应。

记录 16/32/64 位数据的明确字节序规则；以固定报文向量验证，不能仅使用编码后再解码的自洽测试。整数写入必须检查小数和边界，不能静默截断或溢出。

当前 RTU 按设备独占串口。新增同串口多站号功能时，先设计共享总线调度与生命周期，不通过删除重复串口校验直接开放。

## 5. 保持数据与配置可靠

- 配置使用 UTF-8 JSON、稳定 Guid、枚举名称和 `SchemaVersion`。设备、点位与导入的确认操作统一深拷贝候选配置，完整校验后写临时文件并原子替换，保留上一份备份；保存成功才应用当前配置，取消、校验失败与写入失败不污染原配置。首次直接启动默认设备前也须落盘，保持重启后的设备和点位 ID 稳定。
- 仅在配置文件不存在时创建演示配置。损坏、无效或版本不支持的配置应显示错误并保留文件。
- 运行时使用配置深拷贝。停止全部正在采集的设备后才允许修改、导入或应用配置；单设备启停不代表支持运行时热配置，避免编辑对象与工作线程共享可变集合。
- 将平台输入保存在独立草稿，通过页面内“应用设置”提交或“重置修改”恢复。应用时从最新配置克隆并仅覆盖网关/MQTT 字段，保留后来新增的设备；普通设备提交不能覆盖或应用未完成的平台输入。完整配置导入确认后才替换全局配置与平台输入；有未应用平台草稿时禁止启动设备并给出明确提示。
- SQLite 使用参数化 SQL、WAL、事务和串行写入约束。时间存 UTC，UI 显示本地时间；查询时间边界写明语义。
- 历史按保留天数和行数上限清理。数据库增长、写入失败和磁盘满必须可见，不能吞异常后声称数据已保存。
- 遥测 outbox 先持久化再发送；QoS 1 成功确认后删除。失败保留原记录，重启后继续发送。
- 保留稳定 `messageId` 以支持接收端幂等。明确“至少一次”可能重复，不能声称端到端恰好一次。
- 队列满时显式报警并保留旧消息，不静默覆盖未确认记录。根据实际行为记录新快照丢弃或回压策略。
- MQTT 密码仅从配置指定的环境变量读取；配置、日志、导出和 Git 不得包含密码。TLS 使用系统证书验证，不接受所有证书。

## 6. 实现可操作的桌面界面

以中文为默认文案。将总览、设备与点位、实时数据、历史趋势、云端设置和日志按实际任务组织。所有按钮必须连接真实服务；未实现功能不得显示可操作按钮。

修改主窗体、弹窗、动态驱动参数、主题或第三方控件前，阅读 [WinForms DPI 与视觉规范](references/winforms-dpi.md)。保持 `ApplicationHighDpiMode=PerMonitorV2` 与统一的 96 DPI 逻辑尺寸基线；通过 `DpiAwareForm` 管理初始窗口、当前显示器工作区及 DPI 切换，不在 Resize 中递归缩放控件或字体。

使用 `Dock`、`Anchor`、`TableLayoutPanel`、滚动容器和 `AutoSize`。常用文字以 10 pt 为逻辑基准，主要操作提供足够点击面积，状态同时使用文字与颜色。主窗体和弹窗统一字体、色板、间距、图标、按钮命名和确认方式；使用第三方图标时，按所属控件当前 DPI 重绘，妥善释放图像资源，保留依赖和资源许可证。

以当前可用逻辑宽度选择布局。小屏或高缩放时采用工具栏换行、卡片重排与内容滚动，保持导航、设备行启停与配置、平台应用/重置、弹窗确认和取消可达；不缩小字体以强行放下全部内容，不用固定最小窗口尺寸撑出屏幕。动态新增参数控件继承当前字体并只缩放一次，长说明按容器宽度换行，表格行高与自绘图形常量按当前 DPI 计算。

验收覆盖 1366×768、1920×1080、2560×1440、3200×2000 与 100% / 125% / 150% / 175% / 200% 缩放，并检查 100% ↔ 150% ↔ 200% 跨屏及往返无累计缩放。区分真实 Windows DPI、受控布局模拟和实机多屏结果，记录实际系统版本、工作区、DeviceDpi 与截图；未执行组合不得记为通过。

通过 UI 定时器读取线程安全快照。后台不得直接操作控件；异步事件捕获异常，避免 `.Result`、`.Wait()` 阻塞 UI。列表使用稳定 ID 定位，刷新时保持选择和过滤条件。

在设备表每行提供状态、“启动”“停止”和“配置”，按被点击行的稳定设备 ID 执行，不用当前选中行代替目标。删除顶部全局启停与“保存配置”；启用状态是配置许可，与实时运行状态分别显示。启动未启用设备时拒绝；停止已运行设备不修改其启用配置。实时写入按钮按目标设备的运行状态判断，不能只检查网关是否有任意设备运行。参见 [单设备启停与自动保存](../../../docs/device-control-autosave.md)。

单击“配置”列或双击普通设备数据列，统一按被点击行的稳定设备 ID 打开同一个 `DeviceConfigurationDialog`，锁定当前驱动；默认显示“采集设置”，首行提供“启用设备”复选框，按当前设备的 `Enabled` 回显并提交。两种入口在任意设备采集中均只读，启用复选框同样禁止修改。双击事件必须排除启动、停止、配置等操作列，避免单击处理后额外弹窗。工具栏“编辑设备”保留名称、分组、驱动切换及同一 `Enabled` 的编辑功能，不将它替换为专用配置窗。

专用配置窗中，迁移驱动复用原 `ConfigParameter` 元数据；内置 TCP / RTU 分别显示网络 / 串口字段。对话框使用独立草稿，确定后将启用状态、采集设置和驱动参数一起经过完整候选配置校验及原子保存，成功后才生效；取消、校验失败或保存失败均不修改原启用状态。保持设备 ID、名称、分组、驱动、点位及未知参数；`Enabled` 写入设备模型，绑定字段通过采集设置同步，不重复写入 `Properties`。启用仅改变配置许可，不直接启动采集。参见 [设备行内配置](../../../docs/device-configuration.md)。

手动写入要求设备运行、点位启用且允许写入，展示目标与工程值后由操作者确认。记录审计结果。不要默认启用云端远程控制或用配置导入绕过写权限。

导出 CSV 处理引号、逗号、换行和公式前缀，保证中文编码。区分“导入设备”的追加与“导入配置”的整份替换；先反序列化、构造候选、完整校验，整份替换还需确认，原子保存成功后生效。

## 7. 执行有意义的验证

优先测试实际风险：报文拆包、错误 transaction、功能码异常、CRC、数值边界、超时取消、重连、单设备启停隔离与竞态、读写互斥、自动保存失败时原配置保持、平台草稿隔离、配置损坏、队列容量、重启补传和发布确认。

修改完成执行：

```powershell
python scripts/verify-driver-migration.py
dotnet restore EdgeGateway.sln
dotnet build EdgeGateway.sln -c Release --no-restore
dotnet test tests/EdgeGateway.Tests/EdgeGateway.Tests.csproj -c Release --no-build
dotnet run --project src/EdgeGateway.WinForms -c Release --no-build -- --smoke-test
```

清单检查和核心构建测试可在安装对应 SDK、Python 和 Windows targeting pack 的构建机执行；最后一项必须在 Windows 执行。跨平台编译不能替代 Windows 运行检查。迁移测试核对全部 12 个工厂、65 个方法与 74 个源参数，并覆盖适配器线程、坏质量、超时、配置类型和关键真实协议回环。真实串口、PLC、TLS 证书和现场长稳测试按 [验收边界](references/acceptance.md) 补齐。

新增或修改 TCP/HTTP 协议至少覆盖一个真实本地通信回环与一个异常场景。COM/FOCAS 等接口使用对应边界的故障、线程和依赖检查，再补实际 Windows 集成与设备验收，不搭建无关 socket 代替原接口验证。测试应验证外部行为，不为简单属性或固定布局机械编写测试。

## 8. 交付与同步

更新 README 的实际能力、启动步骤、配置示例、边界和验证结果。生成 Windows x64 发布目录，保留数据库和日志在用户数据目录。发布包使用 `.NET 8` 自包含模式时，不需要用户另外安装 Desktop Runtime。

按用户指定仓库和分支提交。提交前检查 diff、构建输出、测试结果与敏感信息；不覆盖已有分支历史。把本 skill 与代码一起提交，使规范持续可追溯。报告实际 commit、构建状态和未执行验收项，不把“配置了 CI”写成“CI 已通过”。
