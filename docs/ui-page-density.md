# 页面留白与列宽整理

日期：2026-10-29。基于 main 的 `2bd403c`，保持 .NET 8、AntdUI 2.4.16 和 Designer 固定控件树。

## 调整

- 八个主页面统一外边距：左右 16、上方 12、下方 8 逻辑像素，减少分页下方装饰空白；侧栏仍为已确认的正常宽度和宽松行高。
- 各页筛选、命令行和设置页操作区使用 `WrappingToolbar` 原生布局宿主，只按可用宽度测量换行高度，不将父容器剩余高度计入首选高度。设备页额外在布局时按当前宽度测量筛选行，防止嵌套自动行高及宽窄往返留下旧高度。没有增加自绘控件。
- 22 个筛选组保留 Designer 中输入列的明确宽度，标签按实际文字测量，去掉整个筛选组预留的多余最小宽度。设备搜索框与其列都为 240 逻辑像素，避免输入宽度上限之外再留一段空槽。标签继续在左、输入在右，空间不足时整组换行。
- 所有 `GatewayTable` 的弹性列先预留可读最小宽度，再按权重分享余量。以完整表格宽度作为官方百分比的基准，单独扣除竖向滚动条，并累计分配整数像素，避免各列向上取整产生多余横向滚动。空间不足时保留横向滚动，不缩小字体。
- 设备名称列参与弹性分配，不再每次布局固定回 150；启停、配置、数量、启用和周期等短列采用适当的固定宽度，名称、驱动、通道、时间和诊断保留较大空间。诊断列不再预留 270 的最小宽度。
- 通信诊断的说明列获得更多余量，当前值和说明使用官方 `Column.LineBreak`，长内容可换行。原生拖动覆盖值、选择、分页和滚动保持路径不变。

固定结构仍由各页 Designer 创建，响应布局不重建控件，不访问应用服务。仅修改界面布局和验证代码。

## 本轮验证

用户明确授权 Release 编译、隔离后台八页面/全部页签布局、宽窄往返、表格拖动及刷新/分页保持、菜单折叠，并允许同范围修复重跑。产物在 `artifacts/ui-page-density/`，使用独立配置和模拟设备；未连接真实设备、外部数据库或 MQTT。

- `build1.log`：完整解决方案 Release 编译成功，0 错误、421 条既有驱动/代理警告；`build2.log` 完整解决方案及最终 `build3.log` WinForms 依赖构建均为 0 错误、1 条既有 `GatewayWorkerClient.cs:283` CS8602 警告。
- `refresh1`：首次后台验证通过，22 张截图。人工复核发现通信诊断长说明仍截断，以及取整产生的横向滚动，因此继续修正，不能只凭首轮断言判定完成。
- `navigation1`：初轮导航验证通过，16 张截图。
- `refresh2`：最终八页面/全部页签验证通过，22 张截图。宽窄往返、工具栏留白、表格填充/最小列宽、诊断表无多余横向滚动、定时刷新稳定性均通过；实时首列通过官方拖动从 261 调整到 333 实际像素，刷新及翻页保持该宽度。
- `navigation2`：最终导航验证通过，16 张截图，100 次折叠计时；宽窄/最大化、八个实际入口、图标位置、筛选保持、首页无横向溢出及既有 250 ms 响应上限均通过。

两项最终运行实际 DPI 均为 192，退出码均为 0，stderr 均为空；独立后台桌面记录 `ProcessWindowVerified=true`、`InputDesktopSwitch=false`。人工检查八页面代表截图以及窄窗口设备和诊断页。此次未再改动已验证的生产代码。

布局检查增加工具栏实际内容底边与容器留白、设备筛选宿主剩余高度、非空表格的填充宽度和各列可读下限，以及诊断表在足够宽度下不得出现横向滚动。保留原有焦点、输入边界、宽窄往返、定时刷新稳定性与列拖动断言。

本轮不执行全量核心测试、现场协议/数据库联调、完整 DPI 矩阵、多显示器或 Visual Studio Designer 往返。历史、日志和数据库列表的本轮页面巡检使用空状态，非空表格交互由设备、40 点模拟实时表与诊断表覆盖；不将空状态巡检当作这些页面的查询功能验收。
