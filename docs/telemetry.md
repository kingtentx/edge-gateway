# 遥测、存储与故障语义

## MQTT 消息

协议为 MQTT 3.1.1，QoS 1，不保留（retain=false），Clean Session。离线队列由本地 SQLite 管理。示例值仅用于说明，程序实际生成对应设备和点位 ID：

```json
{
  "schemaVersion": 1,
  "messageId": "d715df342acd468c900e8d1706611517c",
  "gatewayId": "edge-001",
  "timestamp": "2026-10-22T10:00:00+00:00",
  "samples": [
    {
      "deviceId": "11111111-1111-1111-1111-111111111111",
      "deviceName": "演示机组",
      "tagId": "11111111-1111-1111-1111-111111111101",
      "tagName": "出水温度",
      "address": "sine",
      "rawValue": 50,
      "value": 40,
      "unit": "°C",
      "quality": "Good",
      "timestamp": "2026-10-22T09:59:59+00:00",
      "error": null
    }
  ]
}
```

外层 `timestamp` 是快照生成时间，点位 `timestamp` 是该次采集完成时间，均使用 UTC。云端应按点位时间判断新鲜度，按 `messageId` 去重，并保留质量；不要把 Bad 的 null 转成 0。

## 质量

| 质量 | 含义 |
|---|---|
| Good | 最近一轮真实成功采样且转换有效 |
| Bad | 读失败、缺失、非有限数值、协议异常；值置 null，带错误与失败时间 |
| Uncertain | 采集停止后的显示，或写入成功尚未读回；不可当作新成功数据 |

定时快照收集各点位最新样本，多个点位的采集时间可能不同，不声称所有设备在同一物理时刻采样。历史存储每次采集结果，MQTT 按独立上报周期发送最新值。

## 队列与故障

| 情况 | 行为 |
|---|---|
| 设备掉线 | 生成 Bad 样本，独立退避重连；其他设备继续 |
| 单点设备异常响应 | 该点 Bad；同设备其他可读点继续 |
| MQTT 离线/认证失败/超时 | 已入队消息保留；按退避周期重试 |
| PUBACK 后删除前崩溃 | 该消息可能再次发送；云端按 messageId 幂等 |
| 队列达到容量 | 保留旧消息，当前快照等待入队；暂停生成后续快照并报警 |
| 磁盘写入失败 | 明确记录写入失败；采集不中断，但该历史批次未保存 |
| 正常停止 | 取消采集和发布，等待已接受历史批次处理，关闭驱动，保留未确认队列 |
| 断电/进程强杀 | 已提交 SQLite 事务按数据库机制恢复；尚在内存中的采样/快照不保证保留 |
| 更换 Broker | outbox 保存旧主题和旧消息，发送器使用当前连接配置；UI 会要求明确处理待发送消息 |

SQLite `samples` 保存设备 ID、点位 ID、UTC 毫秒时间与完整样本 JSON，`outbox` 保存主题、消息体、生成时间和递增 ID。历史查询为 `From <= timestamp <= To`，按时间倒序返回，单次最多 10,000 条。

高低阈值目前以状态变化日志呈现，无独立告警确认/工单系统。通信失败不会被误报为阈值恢复；取得新的有效值后才重新判断阈值状态。
