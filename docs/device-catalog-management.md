# 设备分组与通道管理

更新：2026-10-27。

设备管理工具栏新增“分组管理”，并将“通道管理”改为独立列表入口。两者都能在未选择筛选条件时打开，列表显示名称、引用设备数和说明，提供新增、编辑、删除。固定控件与列在 Designer 创建，后台只绑定数据和应用命令。

## 操作与保存

- 分组支持新建空分组，保存后立即出现在设备筛选和设备配置的可编辑下拉中；设备配置也可以输入新名称。删除最后一台设备不会移除分组目录。
- 重命名分组同步更新该组全部设备的 Group，保留设备及点位 ID。名称裁剪首尾空格，长度 1–80，不区分大小写去重。
- 通道支持新增、查看、编辑名称/请求间隔/说明及删除。编辑按所选通道 ID 提交，取消保持管理列表原选择；默认新增名称避开已用名称。
- 设备引用数包含禁用设备。被引用项目禁止删除，需先在设备配置中改组、换通道或改为独立通信；删除前确认。
- 分组与通道修改要求全部设备停止；运行期间可打开列表查看。界面禁用与应用层校验同时约束操作。
- 提交经 IGatewayApplication 命令锁构造最新候选，复用运行时生命周期锁、完整校验与原子保存。弹窗等待成功才关闭；校验或写盘失败保留输入，可直接重试。

## 配置格式边界

模型/JSON 仍为 schema 3，新增 `deviceGroups` 字符串列表，缺省 `[]`。目录与设备当前分组取并集；设备编辑时补齐目录属于设备元数据变化，不触发全局运行设置限制，其他设备继续采集；应用配置命令前后补齐设备使用的分组，避免设备改组或删除后丢失原分组。整份配置替换按导入的目录和设备保存，设备工作簿只导入设备使用的分组，不导入无关空分组。

SQLite 物理结构从版本 5 升为 **6**，新增 `device_groups(slot, position, name)` 强类型关系表，与 current/previous 快照在同一事务中切换。该表不存 JSON；名称和顺序有唯一约束。建库版本号与读取检查共用同一常量。

依照项目开发约定，版本 5 及更早数据库明确拒绝加载，不自动迁移、清空或覆盖。升级时应先使用旧程序导出 schema 3 配置，再使用新的空数据目录导入。此次开发没有打开或修改用户现有运行库。
