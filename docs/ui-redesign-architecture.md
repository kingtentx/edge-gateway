# AntdUI 与 WinForms 设计器重构记录

更新日期：2026-10-26

## 目标

在保持 .NET 8、Windows Forms、现有采集工作进程和 Application/Hosting/Service 分层不变的前提下，将固定页面结构迁移到可视化设计器，并采用 AntdUI 重绘桌面界面。动态驱动参数、数据行、字段映射和趋势内容继续由业务数据驱动生成。

## 当前结构审查

- 解决方案已按 Model、Abstractions、DataAccess、Service、Application、Hosting、Infrastructure.Mqtt、WinForms 及驱动工程分层。
- WinForms 通过 `IGatewayApplication` 调用业务，采集运行由后台 worker/host 承担。此次界面改造不应改变这条调用边界。
- 主窗体以 `MainForm.cs` 和多个分部文件承载业务交互；原仓库没有 `*.Designer.cs` 文件，主窗体固定外壳与页面内部固定布局主要由代码构建。
- 主窗体八个页面分别为运行总览、设备与点位、实时监控、历史与趋势、通信诊断、数据库、平台与系统、运行日志。
- 多个弹窗（设备配置、驱动参数、数据库连接/映射、插件管理、导入预览等）也通过构造函数组装固定表单；需逐个迁移到独立的 Designer/UserControl。
- 页面逻辑文件中存在大量数据绑定、状态刷新、列定义和交互处理。清理时应区分真实业务逻辑、固定布局和测试专用入口，不能仅按文件长度或名称删除代码。

## 设计约定

1. 固定控件层级、工具栏、搜索区、表格容器、页签、弹窗分组和固定按钮放入窗体/UserControl 的 `*.Designer.cs`。
2. 后台代码只保留事件处理、数据绑定、状态同步、业务调用、响应式布局与运行时动态控件。
3. 动态驱动参数根据 `IDriverCatalog` 元数据创建；数据库映射字段按实际 schema 生成；设备/点位/日志数据行不固化在设计器。
4. AntdUI 用于新的统一视觉控件。现有 DPI、键盘、可访问性、托盘、关闭等待、配置原子提交等行为必须保留。
5. 窗体不直接访问驱动报文、数据库 SQL 或采集循环；所有业务操作仍经 `IGatewayApplication`。
6. 清理冗余代码必须以调用关系和测试引用为依据。Smoke/回归入口不是生产冗余代码，不得仅因命名包含 Smoke 就删除。

## 本次已提交

- WinForms 工程增加 AntdUI NuGet 引用（2.4.16）。
- 新增 `MainForm.Designer.cs`，固定定义主窗体的导航栏、顶部状态区域、页面容器和底部操作反馈区；导航控件使用 AntdUI。
- `MainForm.cs` 改为调用 `InitializeComponent()`，导航事件和响应式布局逻辑仍在后台代码。
- 新增 `DevicesPageView.Designer.cs`，将设备/点位页面的标题、工具栏宿主、筛选宿主、设备表格、点位标题/摘要、点位工具栏宿主、点位表格及点位搜索框纳入设计器；设备和点位行、列定义与操作仍由业务代码绑定。
- 新增 `RealtimePageView.Designer.cs` 与 `HistoryPageView.Designer.cs`，固定实时监控与历史查询的标题、筛选控件、表格和趋势区域；查询结果与趋势数据继续动态绑定。
- 新增 `DatabasePageView.Designer.cs`，固定数据库连接/写入组页签、工具栏宿主和数据表格；连接/写入组数据仍由应用层提供。
- 新增 `PlatformPageView.Designer.cs`，固定四个设置页签及应用/重置操作区；表单字段仍由配置模型驱动填充。
- 新增 `DiagnosticsPageView.Designer.cs`，固定通信诊断标题、操作区和诊断表格。
- 新增 `LoggingPageView.Designer.cs`，固定日志设置、运行日志、采样数据三个页签和设置操作区；日志筛选结果与动态查询字段仍由代码驱动。
- 删除数据库页中已被设计器替代的重复 `DatabasePanel` 布局帮助器。

## 尚未完成

- 运行总览页的固定指标卡片/资源图表结构尚未迁移到独立设计器视图。
- 设备配置、驱动详情/参数、数据库连接/写入组编辑器、插件管理、导入预览等弹窗尚未全部迁移到设计器。
- 页面中的部分工具栏、驱动参数和表单字段仍在代码中构建；AntdUI 统一样式、重复控件/样式收敛、进一步冗余代码清理和 DPI 适配审查尚未完成。
- 本轮没有运行构建、测试、架构门禁或 Windows 界面验收；根据仓库约定，这些验证需先获得用户对范围的明确授权。

## 建议迁移顺序

1. 主窗体外壳与共享主题。
2. 设备与点位（固定工具栏/筛选/表格区域，动态列数据保留）。
3. 实时监控、历史趋势、通信诊断、运行日志。
4. 数据库和平台配置。
5. 设备/驱动配置、插件管理、数据库编辑器、导入预览等弹窗。
6. 删除经静态引用分析确认无用的旧样式/重复布局帮助器；更新设计器/DPI 文档并按授权范围验证。
