# 原生 Modbus 连续地址批量读取

日期：2026-10-25。适用 `modbus-tcp`、`modbus-rtu`；配置仍为 schema 3，无新增配置字段。迁移的 `PLC.ModBusMaster` 方法、参数及缓存调用顺序保持原状。

## 行为

原实现每个启用点发送一次读取请求。现在 `ModbusReadPlanner` 对本次 `ReadAsync` 传入的启用点按功能码、地址排序，合并连续或重叠的地址区间，再由 TCP/RTU 共用的 `ModbusDriver` 读取并还原每个点。

- 不跨站号、寄存区或地址空洞；不使用配置里未传入、未到期、未启用的点桥接空洞。
- FC1/2 每批最多 2000 位；FC3/4 每批最多 125 个寄存器。起始地址和范围不越过 65535，Float32/Float64 等多寄存器单点不会被拆成两次请求。
- 每点独立保留类型、字节序和稳定 ID，返回顺序保持调用方的启用点位顺序。位区按相对批次起点的位偏移解码；寄存器 Boolean 仍占一个寄存器。
- 同地址或重叠点可共享同次响应；NaN/Infinity 仅使对应点为 Bad，不污染同批有效点。多批读取不保证整个点表在同一设备时刻取样。
- 批次收到异常码 02（地址）或 03（数据值/数量）时，逐点各读取一次，定位非法地址或兼容不接受大块读取的设备。每批最多增加点数次请求，不递归重试，继续使用原调用方取消令牌和扫描总预算。
- 此回退不缓存设备限制：持续拒绝批次的设备，每轮会多一次失败批量请求。实际设备的小批次限制或清读寄存器等特殊语义仍需按厂商文档联调。
- 其他设备异常（如忙、不支持功能码、设备故障）使相关批次点为 Bad，不展开额外读请求。坏帧、超时、取消和断线仍关闭传输并传播，运行时沿用原故障质量和重连策略。
- 写入路径及设备/通道互斥不变；没有自动重试写入。运行时通信计数仍是驱动调用批次数，不是底层 Modbus 帧数。

协议依据：[Modbus Application Protocol V1.1b3](https://www.modbus.org/file/secure/modbusprotocolspecification.pdf)，6.1–6.4 节。

## 收益和限制

同一寄存区内连续、无故障的 UInt16 点表：

| 点数 | 原逐点请求数 | 当前请求数 |
|---:|---:|---:|
| 100 | 100 | 1 |
| 1000 | 1000 | 8 |

这是实际 TCP 回环逐帧断言的请求数量，不是耗时或现场吞吐倍数。离散地址、混合寄存区、不同扫描周期、回退读取会增加请求数。当前扫描仍在读取完成后等待配置周期，未同时改成固定频率调度；本变更不能用于承诺某台服务器的点位容量。
