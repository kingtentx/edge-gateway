# 单设备启停与配置自动保存

“设备与点位”中的每台设备分别提供运行状态、“启动”“停止”和“配置”。顶部仅保留采集汇总与配置状态，移除全局“启动采集”“停止采集”和“保存配置”按钮。

## 每台设备独立启停

1. 在“设备与点位”找到目标设备，确认“启用”为“是”。未启用时先停止全部运行设备，点击该行“配置”、双击普通数据列，或选中设备后点击工具栏“编辑设备”，均打开同一个配置窗。在默认的“采集设置”页勾选首行“启用设备”，点击“确定”自动保存。
2. 点击该设备行的“启动”。只有这一台设备建立采集会话；其他设备保持各自状态。
3. 在本行状态、“实时监控”或“运行日志”查看连接与采集结果。
4. 点击同一行的“停止”。程序取消并等待这台设备的采集与写入，再释放其驱动；其他已启动设备继续工作。

| 项目 | 行为 |
|---|---|
| 启用 | 在统一配置窗的“采集设置”首行设置，保存后决定是否允许启动及自动启动范围；勾选本身不会开始采集 |
| 启动 | 仅启动该行设备；未启用或已有活跃会话时不可重复启动 |
| 停止 | 仅停止该行会话；不取消设备的“启用”配置 |
| 连接中 / 重连中 | 仍属于已启动的会话，可通过该行“停止”取消 |
| 配置 / 查看 | 所有设备均停止时可编辑；任意设备运行时所有配置只读 |
| 手动写入 | 目标设备必须正在运行，且目标点位启用、允许写入；其他设备运行不能使已停止设备获得写权限 |

共享历史存储与 MQTT 任务在第一台设备启动时建立，停止中间某台设备不会中断这些共享任务。最后一台停止时，程序处理已接收的历史缓冲并关闭共享任务，未确认的 MQTT 消息仍保留在 outbox。

同步厂商调用未在关闭宽限内退出时，仍沿用隔离线程和设备租约保护，待原调用退出后清理；取消采集不等于强制终止本机库调用。

“平台与系统”的自动启动设置仍然有效：启动程序后自动启动全部已启用设备。默认配置未开启自动启动。关闭程序会等待全部运行设备停止；当前产品仍是桌面程序，不是 Windows Service。

## 配置何时保存

添加设备、编辑设备、行内“配置”和普通数据列双击共用同一个 `DeviceConfigurationDialog`。弹窗默认打开“采集设置”，首行“启用设备”复选框读取并提交设备的 `Enabled`，下方统一提供名称、分组、驱动选择、采集周期与通信超时；驱动参数在对应页中配置。行内操作按被点击行的设备 ID 定位，“启动”“停止”“配置/查看”等操作列不走双击配置入口，避免额外弹窗。任意设备采集时禁止新增或修改配置，行内查看的全部字段只读。

新建设备在确认时生成所选驱动的默认点位；编辑已有设备保留设备 ID 与已有点位，切换驱动不自动转换点位，仍需完整校验。同一弹窗中来回切换驱动会保留各自参数草稿。具体字段与模式见 [统一设备配置窗与启用状态](device-configuration-unification.md)。

设备、点位和导入操作使用同一个提交流程：构造独立候选配置 → 校验完整配置 → 原子保存 → 更新当前配置与界面。保存成功才生效，并保留上一版 `gateway.json.bak`。无需额外点击保存按钮。

| 操作 | 提交时机 |
|---|---|
| 添加 / 编辑设备 | 统一配置窗点击“确定”后；仅新建模式生成对应驱动的默认点位 |
| 设备行“配置” / 普通数据列双击 | 同一个统一配置窗点击“确定”后 |
| 添加 / 编辑点位 | 点位编辑器点击“确定”后 |
| 删除设备 / 点位 | 确认删除后 |
| 导入设备 | 读取文件、构造完整合并配置并校验后，仅追加设备 |
| 导入配置 | 确认整份替换后，校验并保存文件中的网关、MQTT 和设备配置 |

取消对话框不会修改原对象，包括尚未确认的启用或停用操作。参数无效、重复标识、串口冲突或文件写入失败时，原配置及启用状态保持不变，界面显示失败原因。启用设备也经过完整配置校验，不会绕过同串口启用设备冲突等检查。首次直接启动默认设备前也会保存配置，避免默认设备与点位的 ID 在重启后变化。

**配置仍在全部设备停止后修改。** 单设备启停没有引入运行时热配置：即使准备编辑的是已停止设备，只要还有其他设备采集，配置界面仍为只读。

## 平台与系统设置

平台输入先保留在页面草稿中，避免在输入主机、主题或网关名称的中间状态立即改变生效配置。

- **应用设置**：对完整候选配置校验并保存，成功后应用本页网关、历史和 MQTT 设置。
- **重置修改**：恢复最近一次已保存的值。
- 有未应用的平台输入时，先应用或重置，再启动设备。
- 普通设备、点位保存与“导入设备”保留未应用的平台输入；应用平台时从最新配置开始，仅覆盖全局与 MQTT 字段，不覆盖后来新增的设备。
- “导入配置”会整份替换，确认并保存成功后也更新平台输入。

变更 MQTT 连接目标时，如果已有待发送消息，仍需确认是否让这些消息使用新连接发送；拒绝确认时保留原配置。该提示与移除顶部保存按钮无关，避免在变更目标时误发积压消息。

## 现有配置与 RTU 示例

配置格式仍为 schema 2；已有设备、点位 ID、地址与驱动参数保留。默认 RTU 示例仍为未启用的 COM11 / 从站 1 / 9600 / 8N1，启用后点击其所在行“启动”。完整步骤见 [COM11 Modbus RTU 示例](modbus-rtu-com11.md)。

所有迁移驱动的专用字段继续按元数据生成，参见 [设备行内配置](device-configuration.md)。单设备启停不改变串口独占校验：两个启用设备不能同时配置同一串口；当前未提供共享串行总线调度。
