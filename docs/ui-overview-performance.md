# 首页折叠性能与控件尺寸修复

日期：2026-10-29。基于 main 的 AntdUI 2.4.16 界面，保留官方控件和固定 Designer 控件树。

## 原因与修改

首页卡顿已在隔离桌面复现。最初减少布局事件未改善耗时；进一步的 .NET 线程采样发现，折叠菜单时 `WM_ERASEBKGND → PaintTransparentBackground → AntdUI.Panel.OnDraw → GdipFillPath` 反复绘制父卡片。卡片首选尺寸测量总计很少，不能把卡顿归因于测量次数或图表数据量。

- `SurfaceCard` 内部布局表由透明底改为与卡片一致的白底，截断重复绘制父卡片的路径；外部圆角、文字、图表仍由 AntdUI 绘制。没有关闭所有动画或添加自绘皮肤。
- `ResponsiveViewport` 在更新内容边界后再次交给 WinForms 计算滚动范围，并在同一重入保护内处理初始布局，避免旧内容宽度留下横向滚动条。
- 自动采集开关在 Designer 指定 52×32 逻辑尺寸；公共 `GatewaySwitch.GetPreferredSize` 提供 52×30 的基本点击范围，并将最大宽度固定为当前 DPI 下的 52 逻辑像素，避免 AutoSize 压成细线或 Dock.Fill 拉成横条。不改变 Checked/事件/保存语义。
- 磁盘进度条用官方 `UseSystemText=true, Text=null` 隐藏第二份百分比；保留右上方使用率与空间警告。动态创建的行在实际 DPI 下显式设置 24 逻辑像素进度行及 Padding，整体高度由标题、详情、Padding 和进度行共同确定，避免初始窗体缩放已经结束后仍使用未缩放行高。

## 折叠耗时

同主机、实际 192 DPI，每种窗口状态 4 次折叠/展开。统计同步点击处理时间，另记录 UI 队列响应；不是显示器帧率或前台视频观感测试。机器负载有波动，报告实际全部样本，不挑选最快的一轮。

| 首页窗口状态 | 修改前均值 ms | 最终复验均值 ms | 最终最大 ms |
|---|---:|---:|---:|
| 宽窗口 | 567.04 | 62.02 | 99.50 |
| 窄窗口 | 627.80 | 94.26 | 112.80 |
| 最大化 | 876.58 | 76.95 | 131.65 |
| 实时资源刷新 | 未单独测量 | 70.44 | 101.82 |

原始基线为 `artifacts/navigation-review/navigation`；最终性能记录为 `artifacts/navigation-optimization/nav-complete` 与 `timings-complete.csv`。导航复验通过，包括 100 次计时（八页面 × 三种窗口 × 四次，另加四次实时资源首页）、连续快速折叠、图标坐标、筛选保持、无横向溢出及首页单次点击/队列 250 ms 回归上限。该上限用于拦截本次半秒至一秒卡顿，不代表 60 FPS。较早的 `nav-final` 在磁盘行 DPI 和开关上限完成前运行；保留该中间记录，最终表格使用全部最终样本。

## 验证记录

按用户已有同范围修复重跑授权执行，全部 UI 测试使用独立后台桌面和临时配置，不连接真实设备/数据库/MQTT。

- Release 构建 `build9.log`：0 错误、1 条既有 GatewayWorkerClient.cs:283 CS8602 警告。
- `nav-complete`：最终构建通过；实际 192 DPI，ProcessWindowVerified=true、InputDesktopSwitch=false，stderr 空，16 张截图。
- `page-refresh-final`：最终构建的八页面及全部数据库/平台/日志页签、40 个模拟点位实际采集、数据源/选择/滚动保持、可见开关严格宽度与自动采集空格切换通过；8 张截图。
- `resources2`：真实资源服务、60 秒趋势/缺失分段、磁盘增删/错误状态、宽窄布局无横向滚动条、进度百分比不重复及详情裁剪断言通过；4 张截图。
- `form-widths3`：最终构建的八页面/全部页签宽窄往返、15 个驱动的设备与点位编辑器、77 个反射参数/65 个方法、动态切换草稿保持、数据库/通道/分组/写入弹窗通过；68 张截图，核对焦点、裁剪和开关实际缩放尺寸。人工检查 FANUC、Modbus TCP 和平台自动采集截图。

保留中间证据：`nav1`/`nav2` 的布局调整未改善性能；`nav-profile` 和 `navigation.nettrace` 用于定位重复绘制，诊断代码已移除；旧版 CPU profile 名称不适用当前 dotnet-trace，失败记录为 `trace.log`，有效采样为 `trace2.log`。`page-refresh` 首轮新增断言误测了尚未选中、未首次布局的页签控件；更正为逐个切换页签后检查实际控件尺寸，未降低尺寸断言。

`resources` 的新增裁剪断言发现动态进度行没有按实际 DPI 缩放；修复动态行的 Padding、固定进度行高及总高度后 `resources2` 通过。中间 `build6.log` 有一条诊断字符串的空引用警告，已修正，最终只剩原有警告。

`form-widths` 截图暴露设备配置开关受 Dock.Fill 拉伸；主动终止该隔离测试进程，保留 4294967295 退出码与截图，不能记为通过。公共 Switch 增加 DPI 宽度上限，并为页面和弹窗增加严格宽度断言。`form-widths2` 又发现初始 HandleCreated 时重设上限过早，将已缩放宽度重置为 52 实际像素；改为在窗体 DPI 事务完成后的布局中约束尺寸，随后复验。

本轮不执行全量核心/协议回归、真实设备/外库/平台联调、完整 DPI 矩阵、跨屏或 Visual Studio Designer 往返。后台测试使用应用内真实控件消息和窗口截图，不能替代未执行的现场与多屏验收。
