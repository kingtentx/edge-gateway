# 驱动 DLL 插件：上传、校验与运行时注册

## 目标

后续新增设备协议不需要修改 WinForms、GatewayHost 或静态项目引用。驱动开发者交付一个针对当前网关契约编译的 .NET 8 DLL；管理员在“平台与系统 → 网关设置 → 驱动 DLL 管理 / 上传”选择该 DLL，安装成功后驱动注册表立即更新，新建设备时即可选择该驱动，无需重启网关。

现有内置驱动仍随程序发布。原始 PluginInterface.IDriver 类型的旧驱动 DLL 不能直接上传；必须由适配器实现本项目的 EdgeGateway.Abstractions.IDriverFactory 和 IDeviceDriver 契约。后续可以逐个把内置驱动迁移为同一插件交付形式。

## 插件契约

- 目标框架：.NET 8 / net8.0，CPU 架构按协议依赖要求选择。
- 必须引用与运行网关匹配版本的 EdgeGateway.Abstractions 与 EdgeGateway.Model。
- DLL 必须公开且只公开一个非抽象 IDriverFactory 实现，具有公共无参构造函数。
- Descriptor.Id 在整个网关中唯一；重复 ID 被拒绝，不会覆盖当前已注册驱动。程序集版本递增后仍须使用新的、唯一的驱动 ID；当前版本不支持原位替换同 ID 驱动。
- 工厂须提供 Descriptor、Create(DeviceConfiguration) 和 Validate(DeviceConfiguration)。驱动实例遵守异步取消、有限超时、质量码与资源释放约定。
- 单 DLL 模式只适用于其依赖可由 .NET 共享框架、网关宿主或该 DLL 自身满足的插件。需要私有托管依赖、.deps.json、原生 DLL、COM 或授权文件的驱动，必须将依赖纳入受控部署方案；单个 DLL 不会凭空包含外部依赖。

## 安装流程与文件布局

1. 选择 DLL；校验扩展名、文件大小、程序集元数据、工厂数量、描述信息和唯一 ID。
2. 计算 SHA-256，将程序集复制到网关可写数据目录下的版本化安装目录。
3. 通过独立 AssemblyLoadContext 加载插件；EdgeGateway.Abstractions 和 EdgeGateway.Model 始终复用宿主程序集，避免接口类型身份不一致。
4. 注册工厂并刷新动态驱动目录；设备编辑器随即可选择新驱动。
5. 在本地安装清单记录程序集文件名、版本、驱动 ID、名称及 SHA-256。启动时重新核对哈希再加载已安装插件。

默认目录：

    <dataDirectory>/plugins/
      installed/<assembly-name>/<assembly-version>/
        <assembly-name>.dll
        driver-plugin.json

原有受信任的 EdgeGateway.Driver.*.dll 目录部署仍支持启动时发现。上传安装的插件由清单发现，避免把它们的普通依赖 DLL 误判为驱动。

## 运行时行为和限制

- 新的唯一驱动 ID 安装后可立即注册；现有运行设备实例不被替换，其他设备采集不需要停止。
- 安装后打开设备新增/编辑窗口，驱动列表从实时注册表读取。创建设备时执行新工厂的参数校验。
- 本版本不支持同 ID 热替换、删除/卸载、自动回滚或在旧驱动仍有实例时卸载程序集。更新现有协议应发布独立驱动 ID；后续需另行实现设备引用检查、旧会话排空、可回收上下文卸载及回滚事务。
- AssemblyLoadContext 不是安全沙箱。插件与网关在同一进程运行，具有该进程权限。只允许管理员从可信来源安装；签名/发布来源审核、反病毒、测试环境验证和最小化运行账户权限仍是部署责任。
- 原生 DLL、COM、厂商 SDK 可能阻止安全卸载，或在原生崩溃时导致整个进程退出。此类驱动应评估独立工作进程 IPC，而不是承诺同进程热加载能够隔离崩溃。
- 安装成功只代表程序集和工厂注册成功，不代表目标设备已连通。还须配置设备参数，执行连接诊断和真实点位读取。

## 验收清单

- 上传有效插件后驱动列表无需重启即可出现。
- 无效 PE、无工厂、多个工厂、重复 ID、缺少依赖和超限文件均明确失败，不影响已运行设备。
- 新插件创建设备后按标准生命周期连接、读取、断线标记 Bad 并重连。
- 设备运行时安装另一唯一 ID 的插件，不停止既有设备。
- 重启网关后从安装清单加载插件，SHA-256 不匹配时拒绝加载。
- 性能比较以相同驱动、设备、点位和采样周期对比基线，记录吞吐、P95/P99 延迟、CPU、GC 与内存；不能仅用“DLL 已加载”作为性能验收。
