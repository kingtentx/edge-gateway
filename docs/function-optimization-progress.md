## 数据库切换原则

设备采集不等待外库 I/O。写入组暂停后不接收新的入库行，已接收数据按原配置排空；UI 明示暂停期间不写入、不自动补齐。更换目标/映射前必须检查该组旧任务和持久缓冲。旧任务未退出或失败缓冲未处理时拒绝危险切换；不删除缓冲、不自动改写目标。不同连接/组可继续运行。新数据只有在明确恢复后进入写入组。


## 日常操作

1. 新增设备、点位后，先用现有“连接与读点诊断”核对读取；“允许采集”表示配置许可，新设备保存后仍需启动。
2. 在设备页点击“数据去向”，或从点位更多菜单/实时监控打开详情。查看完整原始值、工程值、时间、质量和配置路由，跳转实时、采样历史、相关采样日志、设备诊断或数据库写入配置。
3. 标准点行/自定义逐点选择“指定设备 / 分组的启用点位”，后续新增启用点位自动纳入。规则预览只列出匹配设备的点位，空分组始终为空；规则与搜索栏采用左标签、右输入，包含方式与目标同排。手动选择与全局全部仍保留。
4. 已有自定义整行可“复制为新写入组”，默认暂停、新 ID、独立名称。逐字段明确重绑点位、读取元数据并检查预览后再启用，不猜测映射关系、不替换原组。标准与自定义逐点模式的历史查询能力由公共规则即时判断；缺少身份/时间/质量等映射时展示具体原因。
5. 维护活动数据库目标时，暂停相关组，等待按原目标排空，再编辑和恢复。连接参数修改需要该连接下所有组暂停排空。设备和不相关组继续采集/写入。已有失败缓冲不能删除或改投；先恢复原目标补传。
6. 实时监控支持仅异常/未采样、完整详情和一键清除；保留分页和刷新位置。历史页增加最近 15 分钟 / 1 小时 / 24 小时范围，页内条件继续保留；查询与导出仍受原有扫描/条数上限约束。诊断快捷入口按设备 ID 过滤并保留公共输出信息，导出冻结当前范围。
7. 设备分组归属及通道名称/说明变更不重启驱动、清除样本。新增/删除通道或修改间隔仍要求全部设备停止；分组重命名同步更新动态写入规则，相关活动组须先暂停。存在动态引用的空分组也不能直接删除。
