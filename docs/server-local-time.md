# 统一使用采集服务器时间

日期：2026-10-27。用户明确要求外库、运行日志和采样日志等业务时间以服务器时间为准。

## 时间口径

服务器指运行 EdgeGateway 采集宿主的 Windows 主机。使用该主机系统时区，不使用数据库主机时区，也不固定加 8 小时。时区为北京时间时，14:00 的采样在业务表与日志中显示为 14:00。

采样时间保留原采样时刻，记录时间表示生成记录的时刻；排队、重试、补传不把原采样时间替换成当前时间。内部的绝对时刻比较、超时和协议 Unix 时间戳仍表示同一实际时刻。

## 外部数据库

- 标准点行和自定义逐点/整行映射的采样时间、记录时间，按采集服务器时区转换。时间映射为文本时保留服务器时区偏移；未标时区的时间常量按服务器当地时间解释。
- MySQL `DATETIME`、Oracle `TIMESTAMP` / `DATE`、PostgreSQL `timestamp without time zone` 保存服务器当地日期时间；无时区字段读回和历史筛选使用同一规则。
- MySQL 与 Oracle 每次打开连接都设置采集服务器当前时区偏移。MySQL 的 `DateTimeKind` 使用 Unspecified，防止把当地时间误标为 UTC；自定义 MySQL `TIMESTAMP` 绑定按会话偏移保留实际时刻。
- PostgreSQL `timestamptz` 保持实际时刻，连接使用服务器对应的 IANA 时区；Oracle 带时区字段写入服务器当地时间和对应偏移。其他查询工具使用自己的会话时区显示带时区列，需要使用采集服务器时区才能看到相同钟面时间。
- 标准表字段结构与配置 schema 不变。无时区字段无法保存夏令时回拨时的两个相同钟面时刻；需要区分时应使用带时区业务字段。服务器时区应保持稳定，变更后需要重新核对无时区历史。

## 日志与查询导出

运行日志事件时间、采样日志的源采样时间均写为服务器当地时间及明确偏移，例如 `2026-10-27T14:00:00+08:00`。运行日志和采样日志文件名 `yyyyMMdd.log` 按服务器当地写入日期切换，轮转序号规则保持不变。

日志 CSV 的时间列改为“时间（采集服务器）”，按服务器当地时间导出。日志查询仍按实际时刻筛选，历史 UTC 日志可以继续查询；JSONL 导出保留原始日志行，不改写历史证据。
