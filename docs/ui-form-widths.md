# 表单输入宽度

2026-10-28：按用户截图统一优化所有页面及弹窗的单行输入，避免在宽窗口中填满整行。

公共 `InputFrame` 保留 AntdUI 原生绘制及 38 逻辑像素高度，对实际输入容器设宽度上限：数值 200、日期 240、下拉 320、普通文本 360 逻辑像素。父容器不足时继续收缩，已有更窄的筛选输入不主动加宽；宽度按当前 DPI 从逻辑值重新计算，不以缩小字号适配。

地址、数据库主机、平台主机/Token/主题、RPC 主题、点位表达式与写入值在对应 Designer 显式设置 `ContentWidth=560`。点位倍率、偏移、阈值、死区及写入容差虽然使用文本输入，也在 Designer 明确使用 200 上限。动态驱动参数使用相同公共容器和默认类型规则。

固定字段仍在 Designer 创建并加入控件树；本次只调整公共尺寸行为及字段宽度属性。表格、趋势、多行说明和状态输出保持其现有内容布局，业务字段、保存和校验语义不变。

## 验证

经用户授权执行 Release 编译和隔离后台 `FormWidths` 专项。该场景检查八页面和所有页面页签、宽窄窗口往返、设备/点位与动态驱动参数、数据库/通道/分组/写入等弹窗，保留焦点、裁剪和输入高度检查，新增单行输入宽度检查。只使用本地配置及元数据夹具，不启动采集或访问外部数据库。

Release 编译通过：首轮 0 错误、420 条已有驱动及 Worker 警告；最后 `build-3.log` 为 0 错误、1 条已有 GatewayWorkerClient.cs:283 CS8602 警告。

首次 `ui-1` 停在分页条数下拉：旧检查要求所有下拉都有 InputFrame，而分页按既有规范直接使用固定高度的 AntdUI Select。现按分页合同检查实际宽度、高度及可见性，保留普通表单的容器检查。第二次 `ui-2` 停在数据库映射按钮：旧检查在字段映射模式访问仅标准点行模式可见的切换按钮。现先访问标准点行模式检查全部命令，再恢复映射模式继续检查，不跳过按钮。

最终 `ui-3` 通过，应用和后台脚本退出码为 0，stderr 为空，实际 192 DPI，共 68 张 PNG。覆盖八页面全部页签、窄/宽返回、15 个驱动的设备及点位编辑器（77 个反射参数、65 个方法）、显示后动态参数切换、数据库连接及写入组、通道、分组、写入与导入弹窗。输入宽度、高度、焦点和裁剪断言均通过；人工查看日志设置宽/窄截图、平台连接、设备编辑器及最终日志页截图。宽窄检查在同一真实 DPI 下调整窗口，不代表跨屏 DPI 验收。
