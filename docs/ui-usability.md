## 设备与点位的操作语义

设备行的启动、停止和配置直接针对本行设备。界面应让设备名称与这些动作同时容易定位；按可用宽度决定冻结名称列，不能让冻结区占满整个窄表格。双击普通数据列打开相同的配置窗，双击操作列不重复执行命令。

设备级“更多操作”菜单区分所选设备操作与配置交换。“追加导入设备…”追加配置并保留现有网关和平台设置；“替换整份配置…”替换整个配置，要求全停和确认。通道定义通过“通道管理”维护，点位 CSV 与删除等操作归入“点位操作”。删除仍说明目标与外部表、日志文件的保留行为；被写入组选用或字段映射绑定的点位须先调整数据库配置；不能以隐藏菜单项代替这些检查。

点位区使用当前设备作为明确上下文。设备筛选与点位筛选分别显示作用范围和命中数量；无匹配应解释当前条件并允许清除。未选中设备时，添加点位、导入点位等依赖设备的动作不可执行；未选中点位时，编辑、删除和单点读取不可执行。

重绑列表前保存设备和点位 ID。编辑或保存后尽量恢复原目标、当前列及滚动位置；新增点位后定位新点，删除或筛选掉原目标时采用明确的回退选择。保持过滤条件，不因普通刷新清空用户搜索。必须清除条件才能展示新目标时，界面应使这一变化可理解。

保存运行设备或其点位后，只重新连接实际变更的目标设备；其他设备继续采集。未运行设备和新增设备保存后保持停止。配置窗、点位窗和 CSV 预览等待完整校验、原子保存及运行时应用成功后关闭，失败时原窗保留输入。详细事务语义见 [运行中配置](live-configuration.md)。

## 平台草稿与保存反馈

平台页按“平台连接 / 上报策略 / 远程控制 / 网关设置”四个页签浏览，底部应用、重置和草稿状态保持可达。平台专有字段应解释适用平台；平台切换不能悄悄丢弃输入。密码和平台 Token 直接输入并保存到配置及导出文件，输入框使用掩码，日志和诊断继续脱敏。

2026-10-26 按用户要求移除网关设置中的整个“数据目录”展示区域，包括标题、说明和路径；网关身份设置后直接显示驱动插件管理。同步移除仅用于展示路径的窗体字段及构造参数，实际存储目录规则不变。本次只做源码阅读及手动差异审查，未执行构建、测试或界面检查。

“驱动插件管理”按程序集名称一份 DLL 一行显示完整驱动列表，包括随程序提供的原生及迁移驱动，以及上传安装的插件。名称、来源、加载状态优先显示，后续列展示标识、版本、程序集和 SHA-256；较窄窗口可横向滚动。可用性以当前注册目录为准，版本与文件哈希来自宿主登记的元数据，新上传插件立即合并；缺少元数据明确显示未知，只有安装记录却未实际加载的插件保留可见的“未加载”状态。刷新保持所选驱动与阅读位置，读取失败显示原因。

2026-10-25 补齐插件管理：“上传并加载 DLL”“查看详情”“更新 DLL”“删除驱动”，支持双击查看详情。详情显示版本、哈希、能力、参数说明、读取方法和引用设备；内置与上传驱动均可更新或删除，同 DLL 的驱动整组处理，确认时展示全部受影响标识；未加载记录仍可管理。提交期间禁止重复操作与关闭，成功后刷新且保留稳定 ID 上下文；工具栏换行、详情纵向滚动。本次经确认完成 Release 编译、22 项定向测试和架构检查，未执行窗口验收。具体约束与证据见 [驱动插件管理](driver-plugin-management.md)。

2026-10-25 驱动列表修复按用户同意范围完成 WinForms Release 构建（419 条现有迁移驱动警告、0 错误）、架构检查及 6 项定向测试。覆盖无上传插件时的内置目录、即时合并上传元数据、未加载插件、宿主全部 15 个可用驱动，以及原插件安装/重新加载/哈希校验。证据位于 `artifacts/driver-list-20261025/`。未执行全量回归或 Windows 界面烟测，实际弹窗布局尚待界面验收。

应用区域区分已保存、存在未应用修改和当前因设备运行而不能应用。普通设备保存不覆盖平台草稿；应用平台设置从最新配置构建候选，只覆盖属于平台页的字段，保留后来设备变更。重置恢复上次保存内容，设备仍可按已保存设置启停。

对于存在积压的 MQTT 目标变化，应用层预览提供需要确认的目标和待发送数量；用户确认后，应用时再次核对候选与确认凭据。目标或配置已经变化时，不能使用过期确认继续提交。整份替换、删除与真实设备写入继续保留显式确认，普通成功提示不再要求无意义的模态点击。

底部非模态操作反馈显示时间，点击可查看完整结果，说明对哪个对象做了什么。编辑器校验或保存失败时保留内嵌错误详情；可定位的字段提供返回入口。失败不伪装为保存成功；“已保存并调度重新连接”不等于设备已连接。提交期间防止重复点击，退出仍等待安全停止和资源释放。

## 数据库连接与采集写入

“数据库”页包含“数据库连接”和“采集写入组”两个页签。连接支持 MySQL、PostgreSQL、Oracle，填写主机、端口、数据库名 / Oracle 服务名、用户名及密码。密码框使用掩码并保留输入原值。连接窗口另有批次、提交间隔、连接 / 命令超时、共享队列行数和大小（M）配额、最大尝试次数，共 16 个输入控件。测试连接使用当前未保存输入，测试成功不等于已经保存或启用。

写入组按以下步骤配置：

1. 选择已配置的连接，填写独立的 schema 和表名；“读取数据表”可浏览现有表。
2. **标准点行**为默认模式，每个点位每次采样一行，保留 Good、Bad、Uncertain 结果。“全部启用点位”用空筛选表示，并自动覆盖以后新增的启用点位；取消后可搜索、勾选指定点位，选择不依赖 MQTT 上传开关。
3. **自定义逐点**在“点位选择”页选择多个点位，各点位独立写一行、共用映射；**自定义整行**把固定绑定的多个点位组合一行。在“字段映射”页点击“读取 / 刷新字段”。勾选“使用采样”使用采样来源；取消勾选后填写手动常量，该字段仍写入。省略某列需在值来源中选择“不写入”；非空且没有默认值、不是自动生成的列必须全部映射，自动生成列不可操作。目标连接、schema 或表名变化后，保存前必须重新读取字段。
4. 值来源按 `raw_value [原始值]`、`timestamp [采样时间]` 等格式显示，左侧表字段仍是实际目标列名。标准表没有的扩展来源明确标注为采样属性或生成项。自定义整行的采样来源必须绑定实际点位；自定义逐点自动使用当前采样点。整数状态字段取消“使用采样”后填写常量，例如 `192`；“自动”类型按已读取的目标列类型解析。质量来源保持 Good / Bad / Uncertain 文本，不能转换为整数；无效常量在保存前拒绝且保留输入。切换、刷新、重开均保留已配置常量。
5. 自定义整行至少绑定一个采集点位，并配置最小写入间隔、最大样本年龄和 Good 质量要求。只有关联点全部活跃且足够新鲜、至少一个点出现新样本时才形成快照，不持续把旧值写成新记录。
6. 保存连接和写入组后分别启用，再启动设备。连接测试成功后检查当前默认 Schema 下的 `gateway_point`；缺表须在标准点行模式点击“创建数据表”并确认目标。所有模式采集写入均不自动创建表，读取表、字段及保存配置均不修改业务表结构。

数据库配置只能全停后保存；窗口内的异步读取、测试和保存会等待完成，失败显示详情并保留输入。设备运行时可查看状态、测试已保存连接，不能应用数据库配置。连接下所有写入组共享队列配额；页面显示排队、成功写入、丢弃 / 跳过和最近错误。配额满或写入失败不应被“配置已保存”文案掩盖。

## 日志草稿与运行状态

“运行日志”分为“运行记录”和“日志设置”。运行记录列表仅显示最近 500 条网关事件，采集数据默认直接进入 `logs` 下的 JSONL 文件。日志设置包含运行事件最低级别、是否记录采样、单文件大小（M）、保留文件数与天数，显示日志目录入口及待写、累计丢弃、写入失败和文件错误状态。达到大小后轮转，并按数量和时间清理过期日志。

日志草稿可以在采集期间应用，成功后继续采集；普通设备或数据库配置保存不覆盖未应用日志草稿。失败时原已保存设置保持不变，输入与未保存提示保留，用户可修正或重试。重置只恢复日志输入；退出时提示处理未应用日志草稿。平台页不再提供旧 SQLite 历史条数和保留天数设置。

## 实时、历史与诊断

实时、日志、诊断与总览刷新通过统一的 `GridViewState` 保持用户正在看的目标、列、首行及横向滚动位置。实时数据按稳定点位 ID 定位，不能每秒把当前单元格强制移回第一列。筛选后目标不再存在时才重新选择；列表更新不抢走搜索框、菜单或其他正在操作的控件焦点。日志级别以中文显示，双击查看完整详情。

历史页仅列出已启用连接中已启用的标准点行写入组；自定义业务表使用数据库自己的查询工具。未配置可查询写入组时，禁用查询并说明默认数据位于日志文件。历史页保留上次已执行查询的写入组、设备、点位、起止时间、条数和上限提示。用户修改条件后标明需要重新查询；显示旧结果期间，摘要与导出仍明确对应上次查询。选择单点才能生成数值趋势；无趋势时不要以大块空图挤占记录区域。

通信诊断继续区分采集、入队、发送、平台确认、积压、重试与 RPC，并展示采样日志和外部数据库状态；不再显示本地 SQLite 历史条数。长错误可阅读，普通刷新不改变当前诊断目标。协议确认不代表下游业务入库，通信批次数不等于底层物理帧数。

2026-10-25 通信诊断刷新改为绑定同一列表，按行更新有变化的数据；不再每秒替换整表数据源，避免重新生成行时滚动条消失、填充列宽先扩张再收回。新增/删除诊断行按稳定设备/连接 ID 对齐，并恢复选择与滚动位置；设备或连接重名不会混淆行身份。本次用户选择不执行验证，仅完成源码和差异审查，未运行构建或界面检查。

## 小工作区与输入方式

容量单位在软件标签、状态、提示和错误信息中统一显示为 `M`（1 M = 1024 × 1024 字节），替代原 `MiB`；仅调整显示文案，容量数值、限制和计算方式不变。2026-10-25 本次为文案调整，未执行构建或测试。

2026-10-25 输入高度统一：工具栏、筛选区和配置弹窗的单行文本、密码、下拉、数值及日期输入采用与普通操作按钮一致的 38 逻辑像素外观高度，字体确需更多空间时同步增长；内部文字垂直居中。入口集中在 `UiTheme.InputSurface`、`FilterField`、`Toolbar` 和 `EditorDialog.Field`，包含显示后切换驱动生成的参数。多行说明、复选框、导航和表格单元格保留适合内容的布局。详细验证见 [输入区高度统一](input-height.md)。

布局同时考虑可用逻辑宽度和高度。短窗口优先压缩标题、说明和卡片之间的装饰间距，保留正文和输入字体。常用命令不应被多行低频操作挤出首屏；页面外层滚动与表格内部滚动分工明确，避免用户连续切换多个外层滚动区才能找到同一对象。

真实打开下拉菜单后检查屏幕内的位置、文字、禁用态、焦点、键盘选择和 Esc 关闭。平台页签、设备页签和动态驱动参数须逐页访问；固定保存/取消或应用/重置区不能遮挡最后一个字段。所见禁用字段同样检查比例和可见性，不跳过以取得通过结果。

保持 `PerMonitorV2`、96 DPI 逻辑基准及框架统一缩放入口。针对 1366×768、1920×1080、2560×1440、3200×2000 和五档缩放执行 20 个等效工作区组合；真实 100% ↔ 150% ↔ 200% 跨屏、初始高 DPI、远程桌面和文本大小变化另行记录。具体方法见 [DPI 说明](ui-dpi.md)。

## 数据库菜单句柄修复（2026-10-24）

修复前，在实际 192 DPI 环境运行 `--smoke-test`，首次切换数据库页面即可复现 `Win32Exception (1400)`，堆栈为 `NativeWindow.CreateHandle → TabControl.CreateHandle → MainForm.ShowPage`。异常发生在显示页面，不能据此判断配置数据库损坏或目录无权限。

共用的 `EditorTabs` 在 `OnHandleCreated` 中更新页签间距；[.NET 8 TabControl.Padding 实现](https://github.com/dotnet/winforms/blob/v8.0.21/src/System.Windows.Forms/src/System/Windows/Forms/TabControl.cs) 会在句柄已存在时调用 `RecreateHandle`，从而销毁原生创建过程尚未返回的窗口。本次将更新放在 `base.CreateHandle()` 完整返回之后，并阻止创建期间的 DPI 回调提前修改该属性。数据库、平台和日志页面继续使用相同原生页签、字号与 DPI 策略。

新增导航回归在首次显示前设置一个待校正的间距，通过实际导航按钮进入数据库、平台和日志页面，连续三轮选择全部页签并核对原生句柄有效性和当前 DPI 间距。该受控间距输入也能在 96 DPI 触发相同创建风险；它没有修改系统或窗口 DPI。验证脚本要求新增完成标记，保留全部旧断言。
