# 驱动插件管理

更新日期：2026-10-25。入口：平台与系统 → 网关设置 → 驱动插件管理。

## 操作

| 操作 | 行为与限制 |
|---|---|
| 上传并加载 DLL | 安装可信来源、符合当前驱动契约的 .NET 8 DLL；立即注册。重复 ID 提示使用更新入口。 |
| 查看详情 / 双击行 | 查看身份、版本、来源、状态、SHA-256、能力说明、参数和读取方法、引用设备及运行状态。未加载插件不虚构能力。 |
| 更新 DLL | 内置与上传驱动均支持；驱动 ID 和程序集名称不变，程序集版本递增。引用设备必须停止，新工厂须通过完整现有配置校验。成功立即切换工厂，设备保持停止，其他设备继续采集。 |
| 删除驱动 | 内置与上传驱动均支持；任何设备引用（包括已停止或禁用设备）都会拒绝。先删除引用设备或更换驱动。卸载后清除注册和安装记录，重启不会重新加载。 |

源码与默认发布仍提供全部 12 个迁移驱动和 3 个原生驱动，用户可在运行环境更新或删除它们。同 DLL 的驱动整组处理，例如原生 Modbus TCP/RTU 一并更新或删除，界面确认列出全部受影响标识，引用检查覆盖整组。12 个迁移驱动可使用原程序集名称和原接口的新版本 DLL，由 Hosting 注入适配器解析；新第三方插件仍要求单个公开工厂。更新并不等于完成现场设备验收。上传仍是单 DLL，第三方依赖须由宿主环境提供，不把依赖 DLL 当作独立插件；插件在进程内执行，只接受可信来源。

## 一致性与失败处理

UI 仅调用 Application。应用命令锁保证配置和插件提交顺序，Service 的生命周期锁阻止启停、配置提交及停止设备临时诊断与插件变更交错。运行中的其他设备继续工作，操作完成不自动启动已停止的设备。

DLL 先复制到暂存目录，读取同一份字节的程序集身份、哈希和工厂信息。上传程序集从流加载，避免把 DLL 文件持续锁定。新修订文件位于安装目录；每组驱动仅有一个 `driver-plugin.json` 激活清单，更新原子替换其内容。旧修订即使仍在磁盘也不独立参与发现。

清单写入后保存 SQLite 元数据（同 DLL 整组使用同一 SQLite 事务）；保存失败恢复原清单，内存工厂保持不变。若进程在两次持久化之间终止，下次启动以清单为激活依据，校验文件哈希、ID、名称及版本后刷新 SQLite。卸载写入 `Active=false` 停用标记；下次启动再次清理残余元数据。停用标记保留以防止卸载中断后旧记录复活。

启动先读取受管理的驱动身份，再加载未被替换或删除的内置工厂；新版本损坏也不会悄悄回退旧版。成功更新/删除后尝试回收被替换的 DLL 和原始内置 DLL；旧版本以文件方式加载时 Windows 可能暂时占用文件，回收失败不重新激活，下次启动在加载原驱动前再次尝试清理。失败尝试产生的无清单修订可残留，不会被扫描加载。程序不强制垃圾回收或终止线程以强行卸载程序集。磁盘故障导致清单回滚本身失败时报告实际异常并保留候选 DLL，后续启动仍可依据落盘清单恢复。

详情和操作均按稳定驱动 ID 定位。提交期间禁用重复点击和关闭；成功反馈保留在窗口底部，错误完整展示，刷新保持选择和阅读位置。小窗口工具栏可换行，详情可滚动。
