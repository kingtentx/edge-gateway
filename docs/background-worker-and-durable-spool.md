# 后台采集进程与外部数据库持久补传

## 进程边界

生产启动 EdgeGateway.WinForms.exe 时，WinForms 是 IPC 客户端；它会启动或连接同目录的 EdgeGateway.WinForms.exe --worker 子进程。后台进程独占 GatewayHost、设备驱动实例、采集调度、外部数据库连接、MQTT 状态和日志资源。两者通过仅允许当前 Windows 用户访问的本地 Named Pipe 请求/响应通信。

- 关闭 WinForms 不会自动停止采集，也不会释放后台进程拥有的驱动和数据库连接。
- 关闭设备/停止采集命令仍会作用于后台进程。
- WinForms 重开时尝试连接已有 worker；服务无响应时会尝试启动 worker。
- 自动化烟测仍采用隔离的进程内 Host，不启动生产 worker。
- 当前实现提供的是独立后台进程，不等同于已注册的 Windows Service。若需开机无人登录自动运行，应另行部署 Windows Service/计划任务并验证服务账户、权限和恢复策略。
- IPC 只允许本机当前用户，仍应限制程序目录写权限；不要把 Named Pipe 当作远程管理接口。

## 外部数据库采集持久缓冲

采集配置仍保存在 AppData/gateway.config.db。采集写入日志单独保存在 messaging/acquisition-spool.db，不会把采集历史写回配置数据库。

- 每个数据库写入组独立保存批次；批次包含稳定 EventId、UTC 时间和带类型的字段值。
- 在执行外部数据库 I/O 前，批次先通过 SQLite 事务写入 WAL + synchronous=FULL 的持久缓冲。
- 外部数据库确认写入成功后才删除本地批次；启动/运行期间先重放最早的未确认批次。
- 记录写入超时、断线、进程被强制结束后，已提交到 spool 的批次会保留；正常停止或超时排空时也会尽力持久化仍在内存队列的记录。
- 默认持久缓冲上限为 2 GiB / 5,000,000 行。容量耗尽时拒绝新增批次并报告错误，不会静默删除已有未确认记录。
- 对标准点表，event_id 可用于重放去重。自定义映射表使用普通 INSERT，若目标表没有唯一键/幂等键，数据库已提交但本地确认尚未写入时，崩溃恢复可能产生重复行；需要业务表自行设置唯一约束或把 EventId 映射到唯一键。
- 这是 at-least-once 补传，不承诺跨任意第三方数据库和自定义表的 exactly-once。

## 重要边界

当前实现将已经形成的写入批次在外部 I/O 前写入持久缓冲，停止或超时期间也会尽力保存剩余队列。硬断电若发生在采样进入内存 Channel 后、该批次提交到 spool 之前，仍可能丢失这段短暂窗口内的样本。若要求采样一产生就具备断电级无损保证，下一步需把持久化写前日志前移到采集接收边界，并通过批量事务/段文件避免逐点 fsync 带来的吞吐下降。

验收必须覆盖：杀掉 WinForms 后 worker 继续采集；杀掉 worker 后重启恢复；外部数据库断开后恢复补传；spool 容量耗尽；标准点表幂等；自定义业务表重复策略；磁盘满/损坏；24–72 小时真实混合协议长稳。
