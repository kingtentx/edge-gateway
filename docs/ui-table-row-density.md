# 1080p 表格行高

日期：2026-10-29，基于 main 的 `237fff5`。

公共 `GatewayTable` 使用官方 `Gaps = new Size(12, 6)`：横向内边距保持不变，上下内边距由各 12 减为各 6 逻辑像素，AntdUI 负责 DPI 换算。保留原字体、按钮样式及原生测量，不设置固定 RowHeight；所有页面的同类表格共用该规则。

检查发现 AntdUI 2.4.16 的内联 `CellText` 模板按单行测量尺寸，即使 Column.LineBreak 为 true，绘制时换行也不能撑高数据行。公共呈现入口将启用换行且未指定前景色的纯文字交给官方原生文本单元格处理；带颜色的质量文本、按钮、链接和开关保留原模板。没有自绘或逐行手算文字高度。

## 本轮验证

用户已明确授权 Release 编译及后台 1080p 等效行高/按钮/裁剪/诊断换行检查和同范围修复重跑。使用新增的 `RowDensity` 定向入口，仅操作隔离配置和模拟设备，不运行全量测试。

- `artifacts/ui-row-density/build1.log`：Release 构建 0 错误、420 条既有警告。最终 `build3.log`：0 错误、1 条既有 GatewayWorkerClient.cs:283 CS8602 警告。
- `run1` 通过初始行高断言，但人工截图发现诊断两行文字未撑高，不能视为最终通过。
- `run2` 新增换行行高断言失败，确认仅更换列宽不能解决内联文本模板的测量问题；保留 stderr 与失败截图。
- `run3` 最终通过：1920×1080 的名义 100% / 125% / 150% 等效工作区，扣除 48 逻辑像素任务栏；设备、实时和诊断页共 9 张截图。实际窗口 DPI 始终为 192，窗口边界与请求的等效区域一致。设备行实测 70 像素（35 逻辑像素），表头/普通单行 58 像素（29 逻辑像素），150% 等效窄窗口的长诊断行增至 92 像素。模拟设备行启动/停止成功，人工复核按钮居中及诊断两行文字完整。

最终退出码 0，stderr 空，`ProcessWindowVerified=true`、`InputDesktopSwitch=false`。这些是实际 192 DPI 下的等效工作区检查，并非切换显示器 DPI；未执行真实 1080p 屏幕、多屏 DPI 往返、全部页面回归或真实设备测试。
