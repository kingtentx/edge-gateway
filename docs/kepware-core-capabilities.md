# Kepware 核心能力对标与差距功能实现

本轮以 Kepware 的核心采集和数据服务能力作为主要参考，在原有 .NET 8 WinForms 网关上补齐此前列出的六项差距，并增加通道调度、点位扫描周期、故障降速、通信统计和 OPC UA 对外服务。已迁移的 `OPC.UaClient` 继续负责南向读取；新增 `EdgeGateway.OpcUa` 工程负责外部客户端的浏览、读取、订阅和受控写入，两者分别维护。

这份说明描述实际代码与操作方式。自动测试、Windows 原生窗体检查、平台协议回环和现场联调的证据分别记录，不能把“对标”理解为与 Kepware 全部产品、驱动或商业插件功能相同。

## 1. 能力映射

| 采集侧能力 | 本项目实现与操作入口 | 验收要点 |
| --- | --- | --- |
| 通道—设备—点位管理 | 设备页维护通信通道，在统一设备配置窗分配通道，按通道、分组和关键字筛选 | 保存身份与关联；只重连发生变更的运行设备 |
| 通道通信调度 | 同通道采集、诊断、写入互斥；不同通道并行；可配置上一批完成到下一批开始的间隔 | 阻塞一条通道不阻塞其它通道；排队时间不计入设备通信超时 |
| 点位扫描周期 | 设备“扫描与恢复”页选择按设备或按点位周期扫描；点位周期 0 继承设备 | 到期点组成读取子集；不追赶补发超时期间错过的轮次 |
| 故障降速 | 连续失败达到阈值后使用配置的重试间隔；恢复读取后自动回到正常扫描 | 故障设备等待期间释放通道；状态、次数、下次时间可查 |
| 设备与点位诊断 | 设备页“连接诊断”，点位栏“单点读取” | 实际连接及读取，原值、工程值、质量、时间、错误和操作编号 |
| 读写控制 | 实时页“写入选中点位”，核对选项与最终结果窗口 | 仅提交与读回一致分别表达，拒绝未启用或只读目标 |
| 工程量处理 | 倍率/偏移后执行受限数值表达式，编辑器提供试算 | 表达式错误标 Bad，预览和运行使用同一计算器 |
| 批量维护 | 设备复制、20 列点位 CSV、旧 17 列兼容、整份配置交换 | 新身份、冲突校验、整批保存，失败不留半批状态 |
| 诊断统计 | 通信诊断页增加设备读取/写入/失败批次、耗时、降速以及 RPC 状态，可导出 JSON | 批次数不冒充底层帧数，QoS 确认不冒充业务入库 |
| 上报与远程控制 | 周期、变化、变化加心跳；五种 MQTT 模式与白名单读写 RPC | 持久化后推进基线，去重后执行写入，结果可追踪 |
| OPC UA 数据服务 | 独立“OPC UA服务”页配置安全端点、账号与权限，管理客户端证书和服务启停 | 真实 UA TCP 浏览/读取/订阅；稳定节点；质量/源时间戳；写入复用现场权限与锁 |

参考依据是 PTC 官方的[点位属性与扫描周期](https://support.ptc.com/help/kepware/kepware_server/en/kepware/server/properties-tag.html)、[通道串行化说明](https://support.ptc.com/help/kepware/kepware_server/en/kepware/server/tag-management.html)、[故障自动降级](https://www.ptc.com/help/kepware/kepware_server/en/kepware/server/device-properties-auto-demotion.html)以及[通信诊断](https://support.ptc.com/help/kepware/kepware_server/en/kepware/server/channel-diagnostics.html)。这里按本项目实际模型实现对应行为，没有复制 Kepware 的全部扫描模式或 OPC 客户端订阅语义。

## 2. 通道、扫描与设备维护

在设备页点击“添加通道”，设置名称、请求间隔和说明。在设备配置的“采集设置”中选择通道；选择“独立通信”时保留原来每设备独立并行的行为。通道创建、修改和删除目前作为全局调度设置，要求全部设备停止。单台设备的通道归属、扫描模式、点表及参数仍通过配置事务独立应用；其它未改变设备保持采集。通道仍有设备时不可删除，需要先迁移设备。

通道是**通信调度域**，设备驱动仍各自持有连接。它不等于共享 `SerialPort`：同一物理串口依然只允许一个启用设备，原生 RTU 多从站总线共享不在本轮实现范围。连接参数由设备驱动定义，不把不同驱动的参数强行合并为一套通道字段。

“按设备周期扫描”保持旧行为。选择“按点位周期扫描”后，点位的 `ScanIntervalMs` 为 100–3600000 ms，0 继承设备周期。调度使用单调时钟，以本批完成后计算下一次到期；同设备不会重叠执行，也不会在慢设备恢复后连续补发所有错过的轮次。通道请求间隔从上一批结束开始计算，写入与读回核对作为完整操作持有同一通道租约。

故障降速默认关闭，旧配置保持原有指数退避。启用后，连续失败次数范围为 1–30，降速间隔为 100–3600000 ms；正常读取恢复后解除降速。数值表达式计算失败是点位处理错误，不因为公式错误反复关闭正常的设备连接。显式诊断仍可按请求读取；写入必须已有有效的运行会话及连接。

筛选支持通道、设备分组，以及设备名、驱动、点位名和点位地址关键字。复制先生成设备和所有点位的新 Guid、隔离参数字典，默认关闭副本的启用状态；确认使用同一个设备配置窗，保留完整点表。副本保存后不会自动启动。若重新启用后与现有设备存在串口冲突，完整配置校验会拒绝保存。

## 3. 真实诊断与写入核对

停止设备的诊断使用当前已保存配置，创建临时驱动、连接并读取指定点位，完成后释放；不会启动定时采集、历史或 MQTT 任务。运行设备的诊断复用当前会话，通过同一设备锁和通道锁串行执行，返回本次实际读取而非缓存值。没有启用点位时只能报告“仅连接成功”，质量为 Uncertain，不能称为读点成功。

实时页写入时默认勾选“写入后立即读回核对”。可以配置总通信超时（50–60000 ms）、绝对容差及相对容差；界面默认最多 5 次读回、间隔 200 ms。服务接口另支持 1–20 次与 0–5000 ms 的有界参数。写入本身只调用一次，核对失败不会自动重复写入。

| 结果 | 含义 |
| --- | --- |
| Submitted | 驱动完成提交，操作者未要求核对 |
| Matched | 本命令之后主动读回的 Good 工程值满足比较条件 |
| Mismatched | 已读到 Good 值，但限定次数内未匹配 |
| TimedOut | 写入或读回超时，不能推断设备未执行 |
| Failed | 校验、协议或质量失败，详细错误随结果返回 |
| Cancelled | 操作被停止或取消；已发出的写入可能已生效 |

结果携带命令 ID、是否已调用写入、驱动是否确认提交、请求值、实际线类型表示的期望工程值、读回值、质量、次数和时间。64 位整数与十进制值采用精确比较；浮点按照实际可写线类型的舍入结果比较。数值判定为 `绝对误差 <= max(绝对容差, 相对容差 × max(|期望|, |实测|))`。布尔与文本精确比较，不把文本 `"1"` 当作数值 1。

正常完成的主动读回会在同一设备锁内更新共享最新值，保留本次真实质量和源时间戳。读值即使与目标不匹配，也按实测结果显示；超时、取消或已停止会话的迟到结果不会被发布成新 Good。桌面、MQTT 与 OPC UA 读取同一份最新值，后续提交写入、设备停止和重启也遵循同一质量规则。单独执行连接诊断或单点读取不更新采集快照和历史。

本地确认仍保留。RPC 与 OPC UA 复用同一服务入口，并在取得设备锁后再次检查各自的远程写权限。旧 `WriteAsync` 保持只提交语义供已有调用方兼容，新界面、RPC 和 OPC UA 使用 `WriteVerifiedAsync`。

## 4. 计算表达式与 CSV

点位“换算与报警”页新增表达式和试算。`x` 表示倍率与偏移后的工程值，例如 `round(x/10,2)`、`clamp(x,0,100)`。支持 `+ - * / % ^`、括号和 `abs/min/max/clamp/round/floor/ceil/truncate/pow`。不执行 C#、脚本、反射、文件或网络访问。

计算使用 decimal，表达式限制 512 字符、128 个节点、32 层；幂指数为整数 -28…28。超出十进制范围、除零、无效参数和非零下溢明确报错。可以静态判断的错误在保存前拒绝，依赖当前值的错误在采样时成为 Bad。空表达式保留旧类型和旧换算行为。

表达式点只读，服务和配置校验均禁止直接写入；需写设备时使用独立原始点位。当前实现单点数值表达式，不包含跨点位依赖、历史函数或自动反向求解。

CSV 导出增加 `Expression`、`ScanIntervalMs`、`Deadband`，共 20 列，保留 BOM 和 CRLF。旧 17 列仍可导入；按名称更新时，缺失的扩展列保留目标点位原值，新建点位使用空表达式/0/0。明确提供的空 Expression 清除表达式；数值扩展列存在但留空时报错。新增规则仍参与完整的整批候选校验。

## 5. 变化上报与心跳

“平台与系统”提供三种模式：周期全量、仅变化、变化加周期心跳。原配置默认周期模式，上报检查周期沿用 `PublishIntervalMs`。心跳间隔为 100–86400000 ms，不能短于检查周期。

数值死区在点位配置中设置，单位为最终工程量。数值变化相对**上次成功入队快照**计算，微小变化可以累积跨过死区；布尔、文本、数组和对象按类型及内容比较，质量或错误变化独立触发。心跳重发最新样本时保留原采样时间，不伪造新鲜采样。

队列满或入队失败时不推进死区与心跳基线，按原消息 ID 重试。分设备平台报文逐条持久化，完整快照成功后推进基线；中途配置变化时，已落盘片段继续补传，未落盘部分由新配置重建，可能重复但不把失败快照标为已保存。进程启动、配置更新和单台设备重启都会重新发送初值；A 持续运行时停止并重启 B，B 同值首帧也不会被旧基线抑制。

这是最新值上报策略，不是每次采样事件日志：检查周期内短暂变化后恢复，或者队列回压期间的全部中间变化，不会逐条补建。需要完整采样记录时查询本地历史。

## 6. 平台与 RPC

五种模式为 Generic MQTT、ThingsBoard、ThingsCloud、ThingsPanel、IoTSharp。每种具有具体主题、遥测和请求/响应报文，详细认证、子设备状态、协议样例与已核实限制见 [平台接入与 RPC](platform-protocols.md)。密码和 Token 使用环境变量名，配置不保存密文或明文凭据；TLS 仍检查系统信任链。

RPC 默认关闭，远程写入再单独关闭。启用后仅允许已运行、已启用的设备及点位，方法白名单为 `read` 和 `write`；写入还需点位 Writable。拒绝 retained 指令，限制载荷、嵌套层数、队列、处理速率和超时。通过 GUID 或唯一名称定位，不按当前 UI 选中行执行。

远程写前在 SQLite 记录请求占位，完成后持久化结果。重复请求重放原结果，不重复下发；同标识不同内容拒绝。崩溃后只有占位、没有最终结果时返回 Indeterminate，要求核对现场，不自动重写。去重表有容量保护，达到限制明确拒绝新远程写；不静默删除旧命令来腾空间。此语义是防重复调度，不能声称设备端端到端恰好一次。

已有补传报文不会被新配置改写。切换平台类型前必须先完成原平台待传队列；否则配置保存明确拒绝。Broker 确认、平台接口回应与业务系统最终入库分别核对。

## 7. OPC UA 对外访问

“OPC UA服务”页管理北向服务，默认关闭。服务可以独立启动和停止，不会代替或停止设备采集；设备停止、故障或尚未产生样本时，对外读数必须带相应非 Good 质量。设备和点位标识用于生成稳定 NodeId，名称变化不改变客户端绑定；地址空间随保存后的配置更新。

仅开放 Basic256Sha256 / SignAndEncrypt 安全端点，首次运行生成应用证书。客户端与服务端需建立证书信任；界面只导出公共证书，并对导入或移除指定客户端信任提供明确确认。不会自动接受所有证书。匿名会话只读；用户名验证从环境变量读取密码，远程写入默认关闭，即使打开仍须点位可写、设备启用且正在运行。写入通过原有有界读回核对服务，不直接将客户端输入标成现场 Good 值。

具体连接步骤、类型与状态映射、证书目录、配置热更新边界，以及真实协议测试见 [OPC UA 服务说明](opc-ua-server.md)。本轮实现数据访问服务，不宣称已取得 OPC 产品认证，也不把本地 SQLite 历史、阈值日志等同于 UA Historical Access 或 Alarms & Conditions。

## 8. 默认兼容与验证入口

JSON 配置仍为 schema 2：通道列表默认空、设备默认独立通信与设备周期、故障降速关闭、点位表达式空/周期 0/死区 0、周期上报、Generic 平台、RPC 及远程写关闭，OPC UA 服务默认关闭。旧设备与点位身份、驱动参数和原采集语义保留。SQLite 数据库独立升级到 schema 2，新增 RPC 表，保留历史和 outbox。

核心回归入口：`AcquisitionPoliciesTests`、`ExpressionTests`、`DeviceOperationTests`、`PlatformAdapterTests`、`RpcRuntimeTests`、`MqttRpcTransportTests`、`TagCsvExchangeTests`，另有真实 UA TCP 客户端集成测试。Windows 检查增加完整功能操作烟测、通道弹窗、OPC UA 页面与证书管理、读回核对输入的可见性/焦点覆盖；执行八页面、五档缩放对应的 20 个等效工作区组合。

执行记录见 [验证记录](verification.md)。真实 PLC/CNC/串口、用户 OPC UA 客户端与平台租户、24–72 小时长稳仍需要对应环境验收。Windows Service、跨点位计算、共享串口多从站、全部驱动逐帧抓包及 Kepware 全部商业插件不属于本轮完成声明。
